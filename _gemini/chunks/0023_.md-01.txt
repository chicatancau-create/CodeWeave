# 应用端总工程

> 当前审计入口（2026-10-07）：[审计修复记录](../审计修复记录.md)。MSVC/SDK/Qt 6.8.3 已安装并完成环境核验。最新 Qt/QML 页面提交已合入本地 `main`（`cfe0918`）；根目录 EXE 仍是原生 C++23/Win32 回滚入口，Qt 版本必须通过分阶段验收后才允许替换。旧启动链记录已移入备份区。`Main.qml` 当前约 4353 行，CTest 8/8、Node 4/4 和七页真实窗口 smoke 已通过；资源预算和系统专项仍未通过。

## 项目定位

应用端目标是可独立构建、安装、运行、升级和卸载的 Windows 原生桌面软件。Qt 6 + Qt Quick/QML + C++ 预览链可构建和运行；U3 功能/视觉等价、U4 干净 Windows 与性能门禁尚未通过，不能称为 U1–U4/B0–B3 全部验收。根入口仍保留 C++23/Win32 便携 EXE 作为回滚基线。

## 当前门禁补齐计划（2026-10-06，覆盖历史完成声明）

回滚源码基线为 `8dddeb4`，已安装预览与根 Win32 EXE 均保留。只修改应用端，不更改数据格式、密码成本、执行许可或真实账户。按以下顺序实施，缺失样本不得自动通过：

1. 修复后台关闭自等待；回归覆盖 worker 回调主动关闭和主线程最终回收。
2. 部署限定实际使用的 Basic 控件样式，使用 MSVC 允许分发的 app-local CRT，避免附带不执行的运行库安装器；保留图形软件回退，禁止单凭体积删除依赖。构建输出不允许覆盖源码或任意现有目录。
3. 将 Win32 的账户/课程/编辑/执行/挑战/复习/数据工具逐项映射到 Qt；使用已有核心服务及后台任务，新增行为需失败路径与隔离测试。控件 ID 数量不等于视图数量，页面数量也不能证明等价。
4. 增加真实窗口测量：事件处理耗时、滚动帧间隔、按键到绘制、执行取消完成；原始样本带 EXE hash、系统、负载、统计口径。U0a 服务耗时不得冒充 Qt 主线程耗时，窗口出现不得冒充可交互就绪。
5. 最终产物重测工作集/启动及完整包体，超过原门槛保持失败/待取舍，不能由工程师代替用户接受。旧包完整目录与新完整目录比较，单个 EXE 体积仅作补充。
6. 独立干净 Windows 执行安装、跨版本升级、失败恢复、卸载留存数据；开发机隔离目录测试不替代此门禁。用户已确认暂无 VM，先完成本机验证；不擅自启用系统组件或重启。

验收：工作集/交互启动相对增长不超过 20%（否则须用户明确接受）；安装包不超过 50 MiB（否则须接受）；主线程任务 P95 ≤16.7 ms、连续活动帧间隔 P95 ≤20 ms、编辑 P95 ≤50 ms、取消 P95 ≤100 ms；U3 行为及视觉矩阵和 U4 干净系统证据均齐备。失败时不替换根 EXE，不公开发布。具体实测状态写入 Qt 发布候选清单，历史记录只表示当轮执行范围。

本机本轮结果：合并主线后 Qt ON CTest 8/8、Node 4/4、边界门禁和七页真实窗口 smoke 通过；懒加载页面后主线程 P95 0.678 ms、编辑 P95 17.201 ms、取消 P95 71.452 ms。Qt 工作集和窗口出现仍超预算，首次窗口事件仍有约 185 ms 长尾；完整行为/视觉、编辑器专项、实际屏幕呈现和干净系统仍未验收。详细证据见《Qt发布候选清单》和《代码结构》，不把本机采样成功当作资源预算通过。

本次状态修订：2026-10-05。范围仅限应用端；原生重构与真实隔离验证已执行，Qt/QML 基础壳和可重复部署目标已建立，尚未替换根 EXE，未操作真实用户数据、未上传发布。网页端、移动端和其他端的优先级、代码与发布路线不变。

## 优先级

1. **当前最高：Qt Quick/QML 应用端重构**。先完成工程文件、响应性基线和后端任务边界，再建立 Qt 基础壳；保留 C++ 核心与 Win32 回滚入口。
2. **随后：按功能矩阵恢复旧 UI 的行为和视觉**。本轮先提供窗口、导航、状态模型、主题参数和可替换组件骨架；精细视觉复刻由后续 UI 实施者逐页完成，不把占位骨架宣称为完成品。
3. **最后：完整检查与普通安装包**。内部预览安装器已经生成并完成隔离安装、升级、卸载和数据保留验证；正式公开发布仍需完成外部环境和许可证门禁，并另行请求发布授权。

“换 UI”是更换呈现框架，后端继续 C++。QML 是声明式语言，含 JavaScript 表达式/运行时；它没有浏览器 DOM，也不要求 Node，但不能称为“全 C++、所有逻辑都原生编译”。现有 Win32 后端与入口是基线；Qt 迁移已获用户授权并开始实施；当前 U2 状态与验证见后端工程 14.14。

## 本轮执行计划（2026-10-05）

### 目标与完成定义

本轮目标是把应用端从“Win32 可回滚产品 + Qt 方案”推进到“可独立构建的 Qt 基础壳 + 稳定后端契约 + 内部预览安装器”，同时保留可运行的 Win32 入口。当前内部预览已完成；正式公开发布仍以外部环境门禁为准。

- 工程文件明确记录范围、所有者、禁止事项、回滚点和验证命令；
- U0a 原始耗时样本来自隔离合成夹具，写入 `应用端/项目/evidence/`，不含真实账户或工作区；
- U0b 后端任务契约通过核心回归，长任务不会把 UI 线程当作工作线程；
- U1 Qt 目标在 ASCII 构建树中可选构建，Qt 关闭时原有 Win32/Core 构建不回归；
- Qt 基础壳只负责窗口、主题、导航和 DTO 展示，不写文件、不启动进程、不判定学习完成；
- 根目录 `CodeWeave.exe` 在 Qt 通过完整门禁前保持 Win32 版本。

### 本轮明确不做

- 不改网页端、移动端、真实用户数据、数据格式、密码成本或执行白名单；

### 回滚与现场保护
