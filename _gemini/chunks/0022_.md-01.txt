## 1. 当前产品事实

应用端当前入口是 C++23/Win32 原生程序 `G:\CodeWeave\CodeWeave.exe`。运行时不启动 Node、Electron、浏览器、网页服务器或 TCP 端口。发布内容位于程序旁的 `content/`，用户账户和学习数据默认位于 `%LOCALAPPDATA%\CodeWeave` 的账户目录。

当前已接入的后端能力：

| 能力 | 当前实现 | 权威数据位置 | 约束 |
| --- | --- | --- | --- |
| 账户 | 注册、登录、退出、改密、凭据校验、账户目录隔离 | `profile/accounts.v1.tsv` 与账户目录 | 不记录密码；账户之间不得读写对方目录 |
| 草稿 | 原子保存、恢复、超长/损坏保护、账户切换清理 | 账户目录 `drafts/` | 读取失败禁止覆盖；不得把草稿当正式进度 |
| 内容 | 课程、挑战、阶段、starter、提示、练习元数据、hash 校验 | 程序旁 `content/` | 只读；禁止运行时修改发布内容 |
| 执行 | C++、Java、Python、JavaScript 受控运行 | 进程输出与账户轨迹 | Job Object、超时、输出上限、取消、暂停/继续/单步 |
| 轨迹 | 每次执行唯一 session、分页读取 | 账户目录 `execution/trace.v1.log` | 运行结果不得串账户、串 session |
| 挑战 | 输出比较、独立完成判断、正式进度写入 | `learning/progress.v1.log` | 使用提示后不得伪记独立完成 |
| 学习证据 | 本机运行证据与外部实践证据 | `learning/evidence.v1.log` | 外部证据固定 Pending，不自动完成 |
| 复习 | 只读汇总正式证据和进度 | 由账本投影 | 不直接修改学习事实 |
| 导入 | 旧账户、旧学习导出、显式预检与隔离导入 | 用户选择的源 → 新目标目录 | 源只读，目标不得覆盖活动目录 |
| 备份/恢复 | 清单、hash、活动锁检查、恢复到新目录 | 用户选择的备份目录 | 不覆盖现有目标，不复制活动锁 |

## 2. 绝对边界：Flash 不得修改的内容

1. 不修改 `网页端/`、`移动端/` 和任何 UI 样式、窗口布局、控件 ID、文案排版。
2. 不恢复 Electron、Node worker、WebView、HTTP server、命名管道或端口监听。
3. 不把账户、草稿、学习账本、备份、日志或真实工作区复制到发布目录。
4. 不更改密码算法、数据根、权限、执行白名单或账本格式，除非先更新本文件、补迁移方案并完成回滚测试。
5. 不删除 `工作区/`、`备份区/`、真实用户数据、恢复快照或用途不明的文件。
6. 不提交、推送、发布、上传证书，不修改 Windows 信任库。
7. 不使用 `git clean`、`git reset --hard`、宽泛通配符删除或全仓格式化。

UI 只调用后端提供的服务函数并显示结果。后端不得为了“方便”直接操作 HWND 布局；如果缺少 UI 入口，只能记录接口需求，不能顺手改 UI。

## 3. Flash 的低复杂度实现原则

Flash 的任务目标是“容易理解、容易审查、容易回滚”，不是提前做高性能重构。除非本文件另有规定，采用以下简单方案：

- 一个功能一个 `.hpp` 和一个 `.cpp`；公共接口写在头文件，行为写在实现文件。
- 使用现有领域类型和 `Result { ok, message }` 风格；不要引入新的框架、依赖、模板元编程或全局单例。
- 服务按直接调用链组织：`main.cpp → Service → Store/Repository`。不增加事件总线、依赖注入容器、插件系统或自动注册机制。
- 每个公共函数先校验输入，再执行文件/进程操作，最后返回结果；失败立即返回，不吞异常。
- 文件写入使用现有原子写工具；不要手写第二套临时文件、锁或 hash 逻辑。
- 先复制相邻实现的写法，再做最小改动。一次只实现一个功能，避免顺手重命名和重构。
- 变量使用完整名称；函数控制在一个责任内；复杂流程拆成 2～4 个直白的小函数。
- 不使用“以后再处理”的 TODO 作为完成标记。确实暂缓时，在工程文件登记路径、原因和验证命令。

## 4. 后端目录和所有权

```text
应用端/项目/native/src/
├─ main.cpp                    # Win32 事件接入；不扩展 UI 外观
├─ app_core.*                  # 工作区、数据根、锁、草稿原子读写
├─ account.*                   # 账户领域对象
├─ account_store.*             # 账户账本读写
├─ account_service.*           # 注册、登录、退出、改密
├─ password_crypto.*           # 既有 scrypt 兼容校验
├─ content_contract.*          # 内容记录校验
├─ content_repository.*        # catalog/body/starter/hints/exercises 只读读取
├─ content_access.*            # 课程内容访问策略
├─ execution_contract.*        # 执行请求、语言、限制
├─ execution_plan.*            # 工具路径与执行计划
├─ execution_service.*         # 执行生命周期
├─ process_contract.*          # 进程约束
├─ process_runner.*            # Job Object、输出、取消、暂停
├─ trace_contract.* / trace_store.*
├─ challenge_service.*         # 挑战输出判定
├─ progress_store.*            # 正式进度事实
├─ evidence_store.*            # 学习证据账本
├─ external_evidence_service.* # 外部证据校验
├─ review_service.*            # 只读复习汇总
├─ migration_contract.*        # 迁移字段/版本约束
├─ migration_dry_run.*         # 迁移预检
├─ migration_staging.*         # 隔离副本演练
├─ legacy_import.*             # 旧账户/学习导出导入
├─ backup_service.*             # 备份/恢复/清单
├─ native_tests.cpp             # 核心与边界回归
└─ content_delivery_tests.cpp   # 内容包回归
```

所有权规则：

- `main.cpp` 只负责把用户动作转换为服务调用、显示返回消息和管理线程，不直接解析账本格式。
- `Store` 负责持久化，不负责 UI，不负责决定业务是否完成。
- `Service` 负责业务规则和调用顺序，不绕过 Store 直接写文件。
- `Repository` 负责只读内容，不写账户数据。
- `ProcessRunner` 负责进程资源，不判断学习完成。
- `ProgressStore` 只接受已通过挑战/证据规则的正式事实。
- `ReviewService` 只读，不修改证据和进度。
