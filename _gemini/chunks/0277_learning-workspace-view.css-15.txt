   `.main-content` 的整幅宽度，只留 `--pad-page` 一圈安全边距作视觉矩形。

   两条一起出现才算数：`.cw-workspace.is-code-mode`（确实是代码模式，而不是
   沉浸式的别的页）且 `.app-shell.is-immersive`（外壳确实是沉浸式）。只靠后者
   会把首页/内容来源页一起放大，那不是这个动作要的效果。

   用 `:has()` 而不是后代选择器：`.content-wrap` 是 `.cw-workspace` 的**父节点**
   （实测链条 `.content-wrap > .cw-workspace`），写成 `.cw-workspace … .content-wrap`
   永远匹配不到。`:has(> …)` 读作「这个内容列里装着一个处于代码模式的工作台」，
   子组合器与真实层级一致，别的工作台之外的页不受影响。 */
.app-shell.is-immersive .content-wrap:has(> .cw-workspace.is-code-mode) {
  max-width: none;
}

/* ── §5.3 第 3 条：真正停止持续动效（不是放慢） ────────────────────────
   本文件已经不含 @keyframes 与无限动画，因此这里要停掉的是：
   1) 自身保留的悬停/焦点颜色过渡；
   2) 继承自 styles.css 的循环动画（run-indicator 的 blink、变量行的 value-pop）
      —— 用 `animation: none` 掐掉，而不是把 duration 乘 0.35。
   两条触发路径都要覆盖：系统 prefers-reduced-motion 与应用内“减少动效”设置
   （app.tsx 在根节点挂 .reduce-motion）。 */
@media (prefers-reduced-motion: reduce) {
  .cw-workspace,
  .cw-workspace *,
  .cw-workspace *::before,
  .cw-workspace *::after {
    animation: none !important;
    transition: none !important;
    scroll-behavior: auto !important;
  }
}
.reduce-motion .cw-workspace,
.reduce-motion .cw-workspace *,
.reduce-motion .cw-workspace *::before,
.reduce-motion .cw-workspace *::after {
  animation: none !important;
  transition: none !important;
  scroll-behavior: auto !important;
}

/* ── 宽屏“钉进一屏”的预算校准（2026-10-01 实测） ──────────────────────────────
