- 当前选课、最后学习位置和书签执行一次可回滚重定向；双向冲突保留双方供用户选择。
- 草稿与 outbox 按原账户解析；任何待发送事件仍保留原始 ID 及来源 `bundleId + aliasVersion`，由服务端按来源包解析。跨 bundle 不改用 current；来源退役或映射不明时返回冲突并保留原账户队列，也不把 A 账户队列改写到 B。
- 内容回滚后，发布 B 期间产生的 canonical 事实继续保留；A 中没有该内容时显示“内容不可用但事实保留”，重新激活 B 后恢复解析。
- 账户迁移后的客户端不支持新能力时停止写入并保留 outbox，不能悄悄切回 localStorage/原生账本形成第二权威。

## 10. 验收矩阵

| 场景 | 必须证据 |
| --- | --- |
| 内容发布 | dry-run 0 阻断；审批绑定精确候选；发布 job 到终态；候选、附件、current 指针和清单一致 |
| 附件不可变 | 源附件被改写/删除后旧 bundle 仍返回原字节与 SHA-256；篡改 CAS 读取失败；未被引用文件仍 404 |
| 审批时效 | 正文、附件、规则、编译配置及两份映射分别变化后，原审批均返回 409 `approval_stale`，不切换 current；完整重编译或全输入复核能发现变化 |
| 发布幂等与崩溃恢复 | 重复 POST 返回同一 job；同键不同请求 409；candidate、manifest、pointer、job 终态各边界崩溃后恢复唯一结果，旧 attempt 被 fencing 拒绝；特别覆盖“current 已切、journal 仍为 candidate”，不得误删 current 快照 |
| job 终态 | 发布成功、校验失败、资料库不可用和 dry-run 成功，完成后立即和重启后均可按原 ID 查询；202 不再被界面显示为已发布 |
| 发布权限 | 未登录 401；publicContent 下 reader POST dry-run/真实发布均 403 且零副作用；publisher POST 得 202；reader 查询不到他人 job |
| 内容版本固定 | catalog→detail→exercise→asset 任一间隙发布新包，客户端只得完整旧包或整组重载新包；不跨 bundle 混读；退役版本 410 |
| 三端同版本 | Web/Qt/Android 显示相同 serviceInstance、vaultId、bundleId、U01 contentId 与 manifest/正文 hash |
| 附件路径与隐私 | `..`、二次编码、盘符、UNC、分隔符/大小写变体和链接逃逸全部拒绝；API、job、manifest、日志无源绝对路径 |
| 旧内容兼容 | U01 已发布且空映射时为 1 新课程 + 61 legacy；reviewed exact 后旧卡消失且旧选择/深链/草稿/进度可解析；非 exact 不去重不合并 |
| 旧事实冲突 | 旧、新 ID 同时有进度/草稿时双方保留并显式冲突；重复导入幂等；内容回滚后新事实仍保留 |
| 跨版本 alias outbox | 在 bundle A 排队 legacy 事实，bundle B 修改或撤销 alias 后推送；只能按 A 解析或返回显式冲突并保留 outbox，禁止按 current 改归另一门课 |
| 离线 | Qt 不连接时可原生运行；移动端有缓存可只读，无缓存明确空态；共享附件 GC 不破坏保留 bundle |
| 学习幂等 | 同一 `(accountId, changeId)` 同请求重启/断连重试返回原结果；不同请求 409；乱序重复不产生重复事实 |
| 游标与恢复 | cursor 绑定实例/资料库/账户/epoch；跨账户混用拒绝；日志压缩、备份恢复或序号倒退触发全量重同步 |
| 冲突 | 草稿基于同一 revision 的双端修改会保留双方并要求选择，不静默覆盖 |
| 初始化与邀请 | 无邀请注册 403；并发 bootstrap 只有一个成功；过期/撤销/跨实例/重复邀请失败；reader 邀请不能发布 |
| owner 生命周期 | 未绑定默认拒绝；普通账户不能自助认领；转移/恢复原子完成并撤销旧会话；无恢复秘密不能远程恢复；owner.vaultId 不匹配时读取、进度、可见范围和写回均返回 `owner_vault_mismatch` 且零副作用，`publicContent=true` 也不能放行 |

| 安全 | HTTPS、持久会话、授权矩阵、日志脱敏、请求上限、限流和跨站写保护通过 |

## 11. 回滚策略

- **内容与发布状态：** bundle 登记和操作日志 append-only；恢复上一 `activeBundleId` 是一次新的状态转换，不删除 B 的历史、审批或 job。current/status/catalog 始终指向唯一活动版本；客户端固定读取不可用版本时得到明确 409/410 并整组重建。
- **附件：** 客户端缓存按 bundle 隔离，损坏即拒绝使用；服务端 GC 保留 current、回滚目标、正在发布/下载和受支持离线包的引用，清理中断可恢复。
- **网页：** 关闭新内容源后保留现有 legacy 回退；不得用清空 localStorage 作为回滚。旧选择经 alias 解析失败时保留原值并显示迁移待办，不落到错误课程。
- **应用端：** 切回 `PackagedContentSource` 或上一份已校验同步快照；保留本地账户、草稿、账本和按原账户隔离的 outbox。
- **移动端：** 停用同步只影响在线更新；同账户内容回滚可保留经授权缓存，登出/换账户则关闭私密缓存并按用户确认处理未同步项。
- **学习事实：** 数据库迁移前先备份并在副本演练；事件、tombstone、幂等记录和迁移批次不做破坏性物理删除。内容回滚后新 canonical 事实显示为“内容不可用但事实保留”，不把不可解析当删除；冲突未解决不切换权威源。
- **资料库写回：** 沿用现有事务备份和指纹；回滚被第三方修改阻断时保留现场并请求人工处理。
- **服务数据恢复：** 恢复旧 SQLite/文件备份必须验证内容附件引用完整；日志序号倒退时提升 syncEpoch 并要求客户端全量重同步。
- **本次方案文档：** 未实施任何业务变更，无业务回滚要求；两份文档目前未被 Git 跟踪，尚无仓库内历史版本可用于恢复，后续提交归属由 G0 决定。

## 12. 开工前需要用户确认的决策

以下事项会改变架构、真实数据或部署边界，不能在实施时静默决定：

1. 首次服务范围：仅本机、受信任局域网，还是公网；无论选择哪项，非 loopback 前都必须先过 G4。
2. 第一阶段是否只做只读内容（本方案推荐），以及何时开启学习事实同步。
3. 是否授权对 U01 候选包执行首次正式发布；dry-run 通过不等于自动获得发布授权，发布还必须先通过 G1 并绑定精确候选审批。
4. 跨端写入开启后，是否采用单服务 SQLite；若需多实例则改选 PostgreSQL。
5. 既有账户和旧学习记录是否纳入迁移，以及由哪个服务账户作为资料库拥有者。
6. 首次旧课映射只启用哪些 reviewed exact 条目；partial/split/merge/unmapped 是否只展示待办，不进入自动迁移。

在这些事项确认前，可以进行契约补全、隔离 fixtures、门禁实现、单元测试和客户端适配开发，但不得操作真实数据、切换真实 current、迁移真实账户或暴露远程服务。
