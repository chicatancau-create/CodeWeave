# 网页端总工程

## 项目定位

网页端是可独立部署到服务器的浏览器产品，负责界面、交互状态、API 客户端和网页服务发布源。它不携带 Windows 应用端，也不读取应用端本地账户数据。

## 优先级

1. **最高：代码可视化**。先复刻用户提供的视频效果，再确定交互、动画节奏、状态模型和验收指标。本文件不预先编写详细操作指南，避免在没有参考视频时假定错误的视觉行为。
2. **第二：模型任务梳理**。Flash 模型处理可重复、可机械验证的整理工作；后端由 Codex 负责；麦当劳模型负责 UI 交互实现。
3. **第三：稳定性与发布**。完成可视化后，再做接口、性能、可访问性、构建和部署回归。

## 四份工程文件

- `网页端总工程.md`：本总览、边界、优先级和验收门。
- [ 网页端后端工程 ](../网页端后端工程.md)：由 Codex 负责的网页服务、数据、API 和安全工作。
- [ 网页端Flash模型工程 ](../网页端Flash模型工程.md)：千问 3.8 Flash 的重复性任务清单和交付格式。
- [ 网页端麦当劳模型工程 ](../网页端麦当劳模型工程.md)：仅作为 UI 交互模型的任务入口名称，具体内容待用户提供交互参考后由该模型维护。

## 代码可视化范围

当前优先验证可视化是否真实反映代码执行状态：节点、边、变量变化、控制台、时间轴、暂停/继续、错误和完成态必须来自同一运行轨迹。未来收到视频后，按视频逐帧提取状态与过渡，再分配实现任务；在此之前只维护可视化基础契约和测试，不臆造最终视觉。

## 协作边界

- Codex：后端、API 契约、数据一致性、安全边界、可视化运行数据模型、关键测试和最终审查。
- Flash：目录盘点、契约对照、文案/类型机械迁移、测试样例整理、报告生成等可重复工作；不能改变业务规则或删除文件。
- 麦当劳模型：网页 UI、交互状态、布局、动效和可访问性；不得改后端数据语义或越过 API 边界。

## 当前验收门

- 网页端 `typecheck`、`lint`、测试和构建通过。
- 可视化必须有默认可见状态，并能由真实执行轨迹驱动。
- UI 交互不得伪造“已执行”“已掌握”或正式写回结果。
- 发布目录只包含网页制品和明确允许的服务运行文件。

本端本轮的四条改动已交付，逐条如下。**只改呈现与动效，未改后端语义、未越过 API 边界。**

### 1. 代码内容占满整页

用户要求：「只要点进跟代码有关的内容，就直接占满整个页面，左上角留一个返回按键。」

- `learning-workspace-view.tsx`：`codeMode` 初值由 `false` 改为
  `Boolean(lesson.code) || lesson.flow.length > 0`——有代码或有画布的课默认全屏；
  换课时按新课重算（渲染期重置，不用 `useEffect`，避免闪一帧）。
- `styles.css`：代码模式下收起侧栏、装饰框、顶栏，撤销顶栏占用的 `padding-top: 68px`，
  撤掉正文的 `max-width: 1280px` 阅读宽度上限。
- 左上角的「返回」沿用页头原有的 `.back-button`，未新增控件。

### 2. 顶部一体化（去掉分层）

用户要求：「边框顶部有一个 Java 的第一个循环……我希望它全都是一体式的，不要出现明显的分层。」

实测代码模式下工作区之上原有**五条横带**：顶栏（面包屑 + 课名 `contextTitle`）、
资料库同步横幅 `.desktop-vault-settings`、资料来源状态条 `.content-source-banner`、
工作区页头 `.learning-header`、分区导航 `.cw-pane-nav`。

处置：前三条在外壳层收起（`styles.css`），后两条在 `learning-workspace-view.css` 内
收成一条窄带（页头间距收窄、副标题让位、导航下外边距归零）。
**未删除任何 DOM 元素**——状态条只是 `display: none`，普通版式里照旧在，
`role="status"` 与读屏可达性不变。

### 3. 代码逐步显现（画布动效）

用户要求：「一步一步去显现出来……上一步的内容不删，接着把数据显示出来……记得加个流畅的动画。」

- `engine/stage-layout.ts`：`LaidNode` 新增 `enterDx` / `enterDy`（该格中心到画布正中的位移）。
- `components/run-stage.tsx`：位移经内联 `--rs-enter-dx/dy` 下发。
- `components/run-stage.css`：`is-todo` 不画但**保留在 DOM**（读屏要读全程序骨架）、
  `@keyframes rs-node-enter` 让当前拍从正中飞回自己的格子、`is-done` 停在原地、
  idle 边不画。

**动效纪律的变更需要记一笔**：`run-stage.css` 原先明确写着「不含 `@keyframes`」。
这条在本轮按用户要求修改，并在文件头注明了理由与边界——保留的动效只有这一条，
播放一次、无 `infinite`、静态截图仍读得出状态；两条 reduced-motion 降级路径照旧全停。

### 5. 三个运行入口各归其位（本轮追加，2026-10-04）

用户要求：「点击『开始运行』时，中间就会出现最开始的内容……点完之后，可以点击『继续运行』，
是一步到底的运行。内容要一步一步地弹出来，而不是已经完全显现出来。点『单步执行』的话，
就是一步一步地弹，我点一下它动一下。」

改版前 `handleRun` 第一次点击即 `startRun('running')`，一路播到末态——
用户第一眼看到的就是 15/15，「一步一步」当场落空。现在四个入口各管一件事：

| 入口 | 行为 |
|---|---|
| 运行条「开始运行」 | 只落到第一拍就停住（`startRun('paused')`） |
| 运行条「继续运行」 | 逐拍推进到末态（既有 850ms 定时器链） |
| 运行条「单步执行」 | 点一下走一拍（既有 `handleStep`，未改） |
| 画布「播放」 | 第一下直接放到底（新拆出的 `handlePlay`） |

`LearningWorkspaceView` 因此新增一个 `onPlay` prop（`RuntimeTrace` 的 `onTogglePlay` 收它）。
契约测试同步补齐该桩。

**同一轮堵上的一个洞**：减少动效档下，「继续运行」原先直接 `setRunStatus('running')`，
不经过 `startRun` 里那条 `still` 判定，于是「第一次点不播、第二次点开始播」——
等于绕过用户设置。新增的 `resumeRun()` 把这一档也问一遍 `reducedMotion`，命中即落末态。
这条路径是「开始运行停在第一拍」之后才露出来的，改版前不存在。

`use-execution.test.tsx` 里钉「放到底」语义的 5 条用例改走 `handlePlay`
（它们的断言一条没动，改的是入口）。基线未降低：**74 files / 1234 tests**。

### 6. 全站一屏化 · 首页背景 · 文字流程图退场（本轮追加，2026-10-04）

（1）**外壳永不滚**。`desktop-theme.css` 的 `.content-wrap { overflow: auto }` 是整页滚动的
出处。改为 `overflow: hidden` + flex 列；首页由「课程网格 + 右栏」各自成为小框，
挑战页与分析页由页面根成为小框。实测 1480×940 六个视图 `docScroll: 0`，
超长内容全部进小框内滚；1280×800、1024×768 复测同样 `pageScroll: 0`。

（2）**首页流动科技背景找回**。那套动效一直写好（`.shell-decor::after` 七层 +
`cw-bg-drift`/`cw-bg-sheen`），但被 `desktop-theme.css` 的 `display: none` 整层关掉。
放开的同时压到内容之下（`z-index: -1`），因为它带一块不透明底色、原层级高于正文。
工作台与代码模式两条既有开关照旧生效——那两屏仍然没有背景（§5.3 第 1 条）。

（3）**文字流程图彻底退场**。新增 `skeletonStageFrame()`：运行前也把骨架按图形画出来
（全节点未走到、`--` 序号、无数据格），一个假值不编。此前运行前露出的仍是文字拍轨，
而那是用户第一眼看到工作台的时刻。现在画布在所有状态都是图形。

（4）**画布控制条居中**，对齐参考站（原为左对齐）。

基线未降低：**74 files / 1234 tests**；`tsc -b` 与 `pnpm build` 均 exit 0。
