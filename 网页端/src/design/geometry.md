## 2. 形态分配（本文件的主表）

§5.1 形态行原文要求：「黑场、发丝线、编号、局部圆环」并「移除大面积玻璃卡片、渐变按钮和泛光；圆环及细线药丸按模板保留」。「局部」二字是本表的裁定依据——圆环不是全站通用装饰，只在下列位置出现。

| 产品区域 | 允许的模板形态 | 明确禁止 | 模板出处 |
| --- | --- | --- | --- |
| 入口 / 落地 | 发丝线取景框、圆环（品牌标记）、编号眉标、展示标题 | 玻璃卡、渐变按钮 | L89–L96、L115–L121、L237 |
| 全局壳与顶栏 | 发丝线分隔、编号导航、圆点状态指示 | 取景框压过内容层、逐帧变色 | L98–L126 |
| 登录 / 注册 | 细线输入框、细线主按钮、展示标题；**左右两栏**（左＝品牌＋展示标题＋说明，右＝眉标＋表单＋切换＋页脚），中间一条 `--ds-line-hair` 整高发丝竖线（2026-09-29） | 圆环之外的任何持续动画（不强迫观看） | L386–L394（药丸形按钮原形） |
| 学习路径 | 编号阶段（S0—S9）、`.ledger` 式细线清单、`.specs` 式细线键值 | 卡片网格、渐变描边 | L287–L307、`.ledger` 段 |
| 学习工作台 | 黑场分栏 + 1px 发丝线边界、遮光层分区 | **任何**装饰性持续动画（§5.3 第 1 条：编辑器与长文阅读默认静态或低动态） | L190–L209（HUD 只用于非关键装饰） |
| 复习与分析 | `.ledger` / `.specs` 细线表格（§5.2 第六行点名） | 用颜色单独表达语义状态 | L287–L307 |
| 证据回写 | 细线差异表 + 编号 + 固定语义标识 | 泛光、跟随场景的强调色 | 同上 |
| 弹层 / 遮罩 / 账户与设置 | 同字体、同按钮、同焦点、同遮罩体系（§5.2 末行） | 独立一套圆角或阴影 | L419–L456 启动层、L459–L465 无 GPU 降级层（黑场实底的先例） |

三条通用裁定：

1. **圆角**：模板全站只有两种——`50%`（圆点与圆环）与 `100px`（细线药丸）。因此产品侧不得再引入第三种圆角；现有 `--radius: 10px`（`app/src/styles.css` L55）属于被替换对象，不是参照对象。
2. **泛光**：模板圆环用 `box-shadow: 0 0 14px 1px var(--accent)`（L120）、启动标记 `0 0 26px 2px`（L433）。§5.1 要求移除泛光 → 保留 `0 0 0 1.5px` 的**描边环**，删掉后面的发光段。圆环靠描边成立，不靠辉光。**（环本身仍不发光：此条对圆环继续有效，见下方 2026-09-29 反转。）**
3. **发丝线三档不可压成一档**：`--ds-line-frame`（取景框，纯装饰，L94）与分隔线 `--ds-line-hair`（L18）不同用途，混用会让装饰框在正文区变成可见断线。

## 2b. 2026-09-29 反转：黑场上的层级改由冷色发光承担

上面主表「明确禁止」列里的**泛光**与**阴影**两条，前提是浅底 + 黑投影。实际交付是黑场
（`--ds-canvas: #000`），黑投影落在黑底上等于没有——「零投影」不再表示克制，只表示**层级
无法表达**。因此把投影层反过来：黑场里唯一可用的层级手段是**冷色外发光**（`--ds-glow-*`，
`tokens.css` §4.5 / L101–L107）。

反转的确切边界（约束不放松，只是换了极性）：

- **`--ds-shadow-panel` 不再是 `none`**（tokens L179：`var(--ds-glow-panel)`）。凡消费该令牌
  的抬起面自动获得冷色发光，不需要各自改写法。
- **仍不允许裸投影字面量**。每个视图走自己的别名（`--rv-*` / `--lp-*` / `--an-*` / `--cs-*` /
  `--vp-*` / `--cv-*` / `--cw-*` / `--ewb-*` / `--pv-*` 的 `-glow-*` 三档），源码文本不变式
  逐条核。理由同前：视图层不得直接引用裸 `var(--ds-*)`，别名是唯一的消费口径。
- **装饰与状态仍分家**。发光只表层级，不表语义；状态一律仍是「颜色 + 文字 + 图形」三通道，
  且语义状态令牌（`--*-ok/warn/bad/info`）**不消费**任何发光别名。
- **表内 `明确禁止` 列的「泛光」改为禁止 `backdrop-filter` / 渐变 / 模糊函数**
  （`blur()`、`drop-shadow()`、玻璃卡）；真正的泛光现在是允许且被要求的形态。
- 主表「入口 / 落地」行原写「玻璃卡、渐变按钮」——这两条**继续有效**。
  「证据回写」行原写「泛光、跟随场景的强调色」——**泛光**二字失效，改为「模糊函数、
  跟随场景的强调色」；它的语义状态固定色要求不变。
- 圆环 `0 0 0 1.5px` 描边继续不发光（上面 §2 裁定 2 的括注）。
3. **发丝线三档不可压成一档**：`--ds-line-frame`（取景框，纯装饰，L94）与分隔线 `--ds-line-hair`（L18）不同用途，混用会让装饰框在正文区变成可见断线。

## 3. 持续动画清单与处置

模板全站 `infinite` 动画恰好三条，逐条给出处置，不接受「放慢一点」这种 §5.3 明确否掉的做法：

| 动画 | 模板出处 | 产品侧处置 |
| --- | --- | --- |
| `pulse`（圆点呼吸，2.6s） | L130 | 学习工作台与表单区**不使用**；入口若使用，必须被系统 `prefers-reduced-motion` 与 `.reduce-motion` 两条路径各自停成静态终态 |
| `sweep`（扫光，2.4s） | L331 | 属于「泛光」家族，形态上直接不移植 |
| `breathe`（启动标记缩放，2.2s） | L434 | 加载态改为一次性进度 + 文字，不用无限循环；无 GPU 降级层（L419–L465）本身是静态黑场，可以照搬 |

「真正停止」的实现判据（给共享层代理与验收用）：降级后 `animation` 计算值不再是 `infinite` 循环（停掉或改为一次性播放），且**终态可读**——不能停在 `opacity: 0.25` 这类半 invisible 帧上。上表 `pulse` 的关键帧正是 `50% { opacity: 0.25 }`，所以停的时候必须显式给定 1 的终态。

## 4. 装饰层的行为边界

§5.3 第 6 条：装饰层不截获鼠标和键盘、不进入辅助技术阅读顺序。模板实现方式可以照搬，且这两点必须一起搬：

- `pointer-events: none`（L92 `.fx-grain`）；
- 纯装饰元素不带文字内容、不用 `aria-hidden` 之外的语义（模板取景框里没有文字，因此不需要 ARIA；产品侧若用伪元素 `::before/::after` 画框，天然不进阅读顺序）。

模板 FPS/HUD 遥测（`.hud`，字号 9.5–10px，L190–L209）**不**作为产品信息移植：§5.4 明确模板 HUD 仅用于非关键装饰，且 §5.3 第 6 条禁止把 FPS 变成用户必看的信息。

## 5. z 层与弹层重排（README §5 表第 6 行点名的事项）

两侧实测：

| 侧 | 层级（值 → 持有者） |
| --- | --- |
| 模板 | 0 → 背景层；1 → 内容；4 → `main`；6 → 取景框（装饰）；8 → HUD / 章节轨 / chrome；20 → 启动层；22 → 启动层内层 |
| 应用现状（`app/src/styles.css`） | 0 → `.app-shell::before/::after`(L120/L133)、`.code-highlight`(L939)、`.code-tokens`(L958)；1 → `.main-content`(L160)、`.line-numbers`(L894)、`.code-editor textarea`(L917)；15 → `.topbar`(L411)；20 → `.sidebar`(L146)；30 → `.checkin-calendar`(L338)；40 → `.account-menu`(L579)；45 → `.global-search__panel`(L447)、`.notification-panel`(L511)；50 → `.modal-backdrop`(L2121)、`.global-search__input:focus`(L2448)；60 → `.skip-link`(L177) |

三处需要在接入时一并处理的问题，都来自实测，不是推测：

1. **取景框放不进现有层级**。模板把装饰框放在 6（内容 4 之上、chrome 8 之下）。应用内容在 1、顶栏在 15、侧栏在 20，若照搬 6，装饰框会被顶栏与侧栏切掉；若放到 60 以上又会盖住弹层。裁定：装饰层取 **10**（高于内容 1、低于顶栏 15），并且只在入口/落地页挂载，学习工作台与弹层不挂装饰框——这也符合 §5.3 第 1 条「长文阅读与编辑器低动态」。
2. **侧栏压顶栏**。`.sidebar` 20 > `.topbar` 15，而两者都是持久 chrome；细线体系下顶栏与侧栏是同一层的两条线，不该互相遮盖。裁定：把持久 chrome 收在同一档（顶栏与侧栏都取 15，弹层从 40 起）。这条属 M4 全站统一的输入，M3 四页竖切先不改，避免与并行页面代理冲突。
3. **弹层家族缺序**。40（账户菜单）/ 45（搜索面板、通知面板）/ 50（遮罩）之间没有约定：面板比菜单高、但遮罩只比面板高 5。裁定：固定三档 40 = 一次性浮层（菜单、下拉），50 = 模态遮罩 + 模态内容，60 = `.skip-link` 与模态之上的系统级提示；`.global-search__input:focus` 借用的 50（L2448）要随搜索面板归到浮层档，不与模态同值。

`--ds-*` 令牌里未定义 z 档位（tokens.css 只放 CSS 消费的颜色/字体/缓动值），层级常量的落地由共享层代理在 `styles.css` 内决定；本文只规定**档与档的关系**，不规定具体数字除以上裁定外不得新增。

## 6. 与四场景渲染器的关系

§5.3 第 2 条要求 WebGPU 模块按需加载、失败时显示黑场与 CSS 降级并保留所有业务入口。母体里的实现依赖 GSAP 3.13.0 + ScrollTrigger（**standard license，非 MIT**，见 `provenance.md` §2），而本期禁止新增依赖，因此：

- M3/M4 的产品页面**不**引入 GPU 渲染器，形态上用 CSS 实现黑场分区 + 圆环 + 药丸；
- 模板自带一条可照搬的纯 CSS 降级路径：`.nogpu`（L459–L465）就是 `z-index: 22` 的固定层，底色 `#000` 上叠一层 `radial-gradient(120% 90% at 70% 10%, rgba(255,122,47,0.10), transparent 60%)` 的场景色晕。它证明「保留色系及场景过渡」（§5.1）与「无 GPU 时黑场 + CSS 视觉降级」（§5.3 第 2 条）在模板自己的实现里就是同一层，不需要 GPU；产品侧的降级照这条做，静态、不循环、不阻断业务入口。
- 「四场景」只作为色彩场景来源（`--ds-scene-*` 四档）与参考截图基准，学习工作台内固定当前场景（§5.1 场景点缀行），不做逐帧变色；
- 若后续单独决策要引入 GPU 或动效库，许可与打包方式属 03 号方案 §6 外部打包规则与 00 号方案 §7 禁止越界（新外部依赖属重大取舍），需要用户明确批准，本文不预设。
