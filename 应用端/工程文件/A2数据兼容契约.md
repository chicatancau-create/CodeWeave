# A2 数据所有权与迁移契约

> 当前状态（2026-10-05）：原生数据契约已落地并通过隔离测试与真实 Win32 smoke。旧 Electron 字段仅作为显式导入来源，不属于当前运行时依赖；安装器不得覆盖用户数据。

日期：2026-10-04  
状态：原生数据、迁移、备份与恢复契约已实现；真实用户数据仍只通过用户主动选择的导入/恢复流程处理。

## 1. 目标

原生应用拥有自己的账户验证、草稿、正式学习事实、内容快照、事务、备份、锁和恢复流程。Electron 的 HTTP / Cookie / localStorage 不是原生数据契约。网页版及其他端不因原生迁移而修改。

原生正常启动不监听 TCP；主进程调用本地 application service。必要的课程执行进程使用用户态受限 IPC 和操作系统资源控制。迁移器可读取已识别旧数据格式，但只有在来源授权、备份、预检和用户确认后才写入新数据根。

## 2. 数据分类与权威归属

| 分类 | 旧版可见资产 | 权威/风险 | 原生目标规则 |
| --- | --- | --- | --- |
| 账户 | 桌面 runtime users.json，包含 salt/hash、联系信息与资料字段 | 个人敏感；损坏时旧服务只读保护 | 保留 ID、联系信息规范、密码哈希前缀及校验语义；导入只写新 profile，验证成功后才切换；绝不记录密码/hash |
| 登录会话 | 旧版进程内 session Map + Electron HttpOnly Cookie | 运行时凭据，旧进程重启即失效 | 默认要求重新登录，不迁 Cookie/session ID；验证退出和会话过期 |
| 资料库归属/可见性 | 旧 learning owner 数据与用户指定 vault | 正式权限边界 | 不复制、不推断 owner、不改变可见性；只读显示预检结果，用户明确重新绑定 |
| 正式进度与挑战证据 | data/runtime/desktop 学习数据、与 vault 的读写投影/事务 | 学习正式事实；部分事实以 vault 文件为权威 | 先分类权威源与派生副本；冲突/无法解析项逐条报告并隔离，不能取“更新的一份”盲目覆盖 |
| 内容/附件快照 | data/runtime/desktop/content 派生快照；外部 vault 原始 Markdown 与附件 | 原文可能私有；manifest 含稳定 ID/来源 | 不打入安装包。用户选择路径只读扫描、hash 与版本校验，导入仅复制许可快照到新 profile |
| 编辑草稿 | Electron profile/localStorage，及新原生 data/runtime/native/drafts/*.txt | 可能包含未提交源码，尚无统一导出契约 | 不假设 localStorage 等于正式进度；支持显式旧草稿导出、逐条映射、预览和冲突保留；未导出的草稿禁止称迁移完成 |
| 偏好/配置 | Electron profile、desktop-settings.json、workspace config | 含路径、可能本机隐私 | 允许白名单字段导入；剔除 origin、端口、缓存路径与旧运行进程设置 |
| 日志、缓存、锁 | runtime logs、备份槽、临时文件、旧 .server.lock | 可能有路径元数据；锁与实际 PID 紧耦合 | 日志不导入；备份保留供恢复；旧锁不复制，确认旧实例已关闭后由新实例自建锁 |

## 3. 文件格式与兼容性约束

- 当前原生首条草稿格式为 UTF-8 内容文件，ID 仅允许 [A-Za-z0-9_-]{1,96}，路径固定在 data/runtime/native/drafts/。未来要支持多草稿/元数据时引入显式 schema/version，不把任意前端 key 映射成路径。
- 旧账户文件是 JSON 数组，字段至少包含唯一 id、email 或 phone、name、passwordHash；旧哈希格式包括 scrypt$v1$<32 hex salt>:<128 hex derived> 及已兼容的无前缀形式。当前只读提取字段规格，不读取真实文件内容或哈希样本。
- 正式进度、owner、内容 manifest、课程和挑战已按原生契约与非敏感夹具验证；旧学习 localStorage 仍作为历史参考导入，不提升正式进度。网页端 TypeScript 类型仅作为格式参考，不进入原生构建。
- 迁移格式带 schemaVersion、sourceAppVersion、稳定用户/内容 ID、导出时间、记录计数及脱敏完整性摘要。禁止只拷贝未知 JSON 文件后宣称兼容。
- C++ 不自创密码算法。A2 必须证明旧 scrypt 参数、编码和比较语义与应用端目标一致；若需换算法，只有在读旧哈希→登录验证→即时升级新哈希可用且已验证后切换，任何既有账户不应被静默锁死。

## 4. 数据根与锁规则
当前实现：Win32 UI 默认 %LOCALAPPDATA%/CodeWeave，可用 CODEWEAVE_NATIVE_DATA_ROOT 显式覆盖；核心库未传数据根时才使用工作区 data/runtime/native。Electron 使用工作区 data/runtime/desktop。三者不能混称。启动前仍要求有效工作区，不自动创建工作区。本次排除 MSIX；普通安装器未来必须默认保留账户/进度，卸载保留和升级恢复仍须实际验收。


- 核心库未指定数据根的测试写入工作区 data/runtime/native/，和过渡版 data/runtime/desktop/ 分开。它不会自动读取 desktop users.json 或 vault 写回文件。
- 发布产品最终用户数据默认应位于 %LOCALAPPDATA%/CodeWeave/ 下产品独立目录；可允许用户指定工作区/资料库路径，但应用 profile、账户与日志不因工作区移动而意外消失。最终目录方案需在 A2 根据当前配置和用户实际路径证据确认。
- 单实例锁须原子创建、明确所有者、随进程句柄释放，并能区分活进程占用与崩溃残留。清残留必须检查进程身份；不按文件名无条件删锁。
- 原子写先在同卷唯一临时文件完成并 flush，检查写失败，然后原子 replace；旧版失败不得先删除目标。正式事实还需备份/校验，草稿则需确认编辑器已报告写入成功才标保存。
- 两个进程不可同时写同一 profile。恢复旧版/新版程序时，确认进程退出和锁释放后再切换；不要让旧 Electron 与原生 app 并发读写不同副本并伪装同步。

## 5. 只读预检与迁移流程

1. 盘点：列出旧工作区根、profile 根、文件名/大小/版本/mtime/hash 和目录元信息。默认不打印内容，不加载凭据，不对源文件执行修复或清理。
2. 资格检查：用户选择要迁移的 workspace/profile，确认账户归属和 vault 所有人；哈希只用内存判格式，不输出具体值。失败即报告来源与原因，不做写操作。
3. Dry-run：产生字段/ID 映射、数量、冲突、超大/未知文件、无可解析草稿清单和预计目标磁盘空间；目标根仍不写业务数据。
4. 备份：用户确认后关闭旧应用及服务，对源数据做一致性备份；记录相对路径、文件大小和加密哈希，验证备份可读。原目录保持只读且原位保留。
5. 副本演练：只将副本导入临时隔离 profile，运行 schema/唯一性、账户验证（用专用测试凭据、不输出凭据）、学习事实/manifest 引用、草稿数和文件 hash 检查；测试写入中断/磁盘满/重复运行。
6. 用户确认：显示数据来源、目标、变更数量、冲突、需重新登录以及未迁移内容，逐项确认。确认之前不切换正式 profile。
7. 提交：新 profile 写入临时版本并全量校验，通过后以目录级原子选择/版本指针切换；失败保持旧 profile 为活动源，丢弃本次专属临时副本需要另按临时文件清理门禁处理。
8. 回滚：用户选择旧程序时必须确保旧数据版本兼容。切回旧源前导出原生版本后产生的新进度/草稿；不以删除新写入来“回滚”。

## 6. 故障与验收矩阵

| 场景 | 预期行为 | 通过证据 |
| --- | --- | --- |
| JSON 无效、字段缺失/重复 ID | 只读拒绝，原源 hash 不变 | 隔离副本测试 + dry-run 报告 |
| 旧账户 salt/hash 格式 | 旧账户可验证且不泄露凭据；成功后按迁移设计处理 | 固定假数据测试向量，不读真实 hash |
| 进度/课程 ID 冲突 | 保留双方、输出可审查冲突项，不自动择一 | 同 ID 冲突夹具 |
| 草稿超长/含 NUL/UTF-8 非法 | 明确拒绝或可逆导出，不截断为成功 | 边界与损坏编码测试 |
| 重复迁移 | 幂等，不能复制重复账户或进度 | 同输入 dry-run/commit 两次 |
| 临时写入中断/磁盘满 | 活动源不切换，目标残缺不呈现为完成 | 故障注入、源/目标 hash 对比 |
| 原生锁占用/崩溃残留 | 不并发写；活进程锁不删除；死进程恢复路径可审计 | 多进程并发与杀进程隔离测试 |
| 旧/新版本回退 | 回退前保全新记录并校验可重新导入 | 前向与回退完整往返演练 |
