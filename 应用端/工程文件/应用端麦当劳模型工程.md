# 应用端界面与交互工程：Qt Quick/QML 重建方案

修订：2026-10-05。**正式首选：Qt 6 + Qt Quick/QML + C++。状态：环境已就绪，进入 P0/U0a 实施准备；尚未创建 Qt 产品源码，尚未替换 EXE。** 服从 [总工程](总工程/应用端总工程.md)，后端契约见 [后端工程第 14 节](应用端后端工程.md)。

## 1. 为什么选 Qt

符合无浏览器引擎、自定义视觉、C++ 核心复用三项要求，并提供成熟的窗口、文本输入和无障碍基础设施。相比继续堆叠 Win32 owner-draw，能减少自研布局、动画和控件成本。Qt 不是绝对性能冠军；QML 有布局、绑定、JavaScript 与场景图开销，需要工程优化和实测。

当前 Win32 界面是默认系统控件，未复刻原网页视觉。因此原生业务功能接通不等于原界面恢复。后续不是重做业务和数据，而是重建呈现层、补齐 UI 适配与异步调度。保留现有 C++ 服务、账本、内容和进度规则。

## 2. 实施边界

- Windows x64 首发，Qt Quick 独立窗口（QQuickWindow/QQuickView），动态链接获准的 LGPL Qt 模块；不使用 WebEngine、WebView 或浏览器服务。
- 业务唯一事实源为 `codeweave-core`。QObject facade 转换属性、命令、DTO 与信号，QAbstractListModel 只提供必要行；QML 不写盘、不调用 shell、不判学习完成。
- 不要求在 UI 迁移前把整个核心变成跨平台；保留 Windows CNG、Job Object、原子替换和文件锁实现。
- 原网页界面用于只读视觉参考，不能导入 DOM/CSS/renderer 作为运行时。颜色、间距、字体等转为 QML 设计参数；图标和字体先检查授权。
- 不承诺“全部业务代码一行不动”：允许抽离 main.cpp 中的调度与呈现耦合，按后端第 14 节拆分职责；不重写既有数据契约。

## 3. 视觉与功能对照清单

U0 固定原界面截图/参考构建与来源版本；已有可信材料优先，不打开真实用户资料做演示。缺少参考的区域先登记，不能自行宣称复刻一致。

| 区域 | 必须保持的用户行为 | Qt 接入与验收 |
| --- | --- | --- |
| 主窗口/导航 | 页面、当前课程、焦点和键盘切换可达 | Main.qml + 轻量页面组件，1366×768 与 DPI 实机测试 |
| 课程与挑战 | 74 项内容、选中项、正文、starter、提示与外部策略 | 虚拟化 ListView；只传当前页面数据，选择后显示明确载入/错误状态 |
| 编辑器 | 中文 IME、选择、剪贴板、撤销/重做、Tab 缩进、行号、高亮、草稿保护 | 编辑器原型先验收，再大范围做视觉复刻 |
| 运行控制 | 运行、暂停/继续/步进/取消、busy/error 状态 | 命令只走 facade；执行真实语义，按钮不会伪造调试状态 |
| 输出/轨迹/画布 | 运行结果与 session 对应，可滚动查阅 | 从轨迹快照呈现；没有变量/行级事件时不编造执行动画；需要扩展轨迹另立契约任务 |
| 账户/数据 | 注册登录改密退出、备份恢复、旧数据导入 | 背景任务、进度、取消、安全关闭、失败恢复；切账户清空呈现 |
| 进度/复习/证据 | 正式进度与 Pending 区分、辅助与独立完成区分 | 只读模型，不在 QML 增加“完成”判断或另一份数据库 |

每个页面验收同时覆盖加载、空态、成功、失败、任务忙、取消、账户切换、关闭重启；截图一致不能替代行为验证。

## 4. 编辑器方案（已选 Qt 主路线下的组件设计）

默认先验证 Qt Quick TextEdit/TextArea + QQuickTextDocument/QSyntaxHighlighter 的轻量编辑器：Qt 负责输入法、文本选择、撤销；我们补行号、缩进、基础语法高亮和错误定位。按所选 Qt 版本的公开 API 接入，禁止使用私有头文件。它不是现成 IDE，不能承诺折叠、补全和多光标自动具备。

QScintilla 不纳入默认闭源免费依赖：官方为 GPLv3/商业双许可，且属于 QWidget，无法直接当作 QML 控件“免费插入”。动态链接 QScintilla 不会把其 GPL 变成 LGPL。

若原型在课程规模和长文件测试不能达标，先优化增量高亮、显示区与信号次数；仍不达标时，评估 [Scintilla 原生控件](https://www.scintilla.org/License.txt) 的宽松许可及嵌入成本，单独验证 HWND 合成、焦点、IME、DPI、遮挡和无障碍；或按用户预算选择商业组件。不得偷偷换成 Monaco/WebView，也不得因现成编辑器不兼容就重写整个 UI 框架。

测试夹具：常规课程代码、1 MiB 长文件、当前草稿上限边界、CRLF/LF、emoji/组合字符、中文 IME 组合输入；保存与恢复校验内容 hash。先按核心真实大小限制设置边界，不用截断代码换取流畅。Ctrl+Z/Y、复制粘贴、候选窗位置、滚动高亮和只读坏草稿必须实测。

## 5. 绘制与性能实现规则

- 先用 Qt Quick 基础图元、Shapes、缓存静态纹理/渐变实现界面；发光动画限定可见区域和刷新频率，优先合成变换，避免每帧重建大型节点树。
- 列表复用 delegate，输出与轨迹分页/按需载入；不创建几千个隐藏控件，不用全树绑定反复计算进度。
- 关闭或不可见页面停止动画，最小化窗口暂停装饰动画；支持减少动态效果。动画效果不能阻塞编辑和取消。
- 高频输出批量通知，限制队列与显示行数，完整事实按核心规则保留；图形渲染线程不得直接操作账户服务和 QML GUI 对象。
- Qt Canvas Painter 不纳入本项目默认 LGPL 依赖，Qt 6.11 官方许可列其为 GPLv3 模块。普通 Qt Quick 场景图已可原生渲染，不依赖该模块才能绘制黑色画布或发光效果。

## 6. 实施顺序与交付

1. P0/U0a：先冻结工程文件和范围，再用隔离夹具测备份、导入、账户操作耗时；只保存原始样本，不提前写性能结论。
2. U0b/U0c：按后端工程契约移出长任务，一次只迁移一条调用链，区分线程改进与框架改进。
3. U1：核对 Qt 模块许可/工具链/CRT 后创建独立 Qt 目标；空窗口、列表、编辑器、动画分开计时。同机结果按总工程预算优化。
4. U2：冻结 facade 的字段与命令，统一后台任务和账户代次；增加适配测试；核心保持无 Qt 测试构建。
5. U3：按上表一块一块复刻，复用已验收组件；每次只改明确文件，不能视觉/线程/账本三层同时重写。
6. U4：验证完整 Qt 运行包与 manifest，在无开发环境 Windows 做中文路径、IME、DPI、读屏、RDP/GPU 降级及安装生命周期验收。

可访问性由 Qt 提供基础能力，自定义控件仍须 Accessible 名称/角色/状态、键盘焦点、对比度和 Narrator 实测；不能写成“框架白送，无需验收”。

当前 Win32 的 HWND 自动化不能直接测 Qt。核心 CTest 继续保留，QML/模型补 Qt Quick Test，端到端使用 Qt 可访问性/UIA 或适配驱动验证真实窗口，不能只跑旧脚本后宣称 Qt 通过。基础壳阶段只验收窗口生命周期、主题参数、导航状态和 facade 占位接口；旧 UI 的精细间距、动效、图标和编辑器皮肤交给后续 UI 实施者逐页完成。

切换根 EXE 的条件：页面矩阵、后端回归、性能预算、编辑器/IME、许可与完整运行包全部通过。切换前保存旧已验证包并校验 hash；数据格式不变，旧新不并行写同一 profile。若失败，关闭新实例后切回 Win32 包，保留新产生的用户数据。正式 Qt 交付只保留一套活动 UI，旧包在恢复区，实验目录按后端清理规则移除。

## 7. 可交给 Flash 的工作

线程/锁、核心契约、编辑器集成、许可与CRT由负责人定稿。Flash 只基于已验收样例复制单一组件、绑定已声明 DTO、增加固定测试数据、运行命令和记录差异；不自行设计通用框架，不自行降低验收阈值。用户未下达实施指令前，只维护本方案。

官方资料与许可核验链接统一见 [总工程](总工程/应用端总工程.md)，不在每个角色文档复制会过期的版本表。
