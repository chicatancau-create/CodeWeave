# CodeWeave 项目代码结构

根目录 `CodeWeave.exe` 现在是 C++23/Win32 原生应用。应用运行需要同目录 `content/` 和 `config/codeweave.config.example.json`；用户数据写入 `%LOCALAPPDATA%/CodeWeave`，不写入程序目录。

```text
G:/CodeWeave/
├─ CodeWeave Qt 预览.lnk         # 本机 Qt 入口，指向用户安装目录，不入 Git
├─ CodeWeave.exe                 # 保留的 Win32 回滚入口
├─ content/                      # 根入口随包课程内容：74 条课程/挑战，正文、starter、提示、元数据
├─ config/codeweave.config.example.json
├─ 工作区/                       # 用户明确选择的有效工作区标记与资料库
├─ 应用端/
│  ├─ native/src/
│  │  ├─ main.cpp                # Win32 窗口、课程选择、账户、草稿、执行、数据菜单
│  │  ├─ backend_benchmark.cpp   # U0a 隔离后端耗时原始样本工具（不读取真实数据）
│  │  ├─ app_core.*              # 工作区校验、用户数据根、原子草稿、单实例锁
│  │  ├─ account_*.*             # 账户注册、登录、改密、scrypt 兼容验证与账户根
│  │  ├─ content_*.*             # catalog/body/exercises/starter/hints 只读内容仓库
│  │  ├─ learning_*.*            # 证据、正式进度、挑战、复习投影
│  │  ├─ external_evidence_*.*   # 外部环境证据校验与待人工确认记录
│  │  ├─ execution_*.*           # 请求、计划、四语言运行、输出和取消
│  │  ├─ process_*.*             # Windows Job Object、暂停/继续/单步、子进程清理
│  │  ├─ trace_*.*                # 每次运行唯一 session 的轨迹账本
│  │  ├─ migration_*.*            # 迁移预检、契约和隔离夹具
│  │  ├─ legacy_import.*          # 旧 users.json/学习导出严格导入到新目录
│  │  ├─ backup_service.*         # 新目录备份、恢复、清单指纹与活动锁排除
│  │  ├─ native_tests.cpp         # 核心、边界、账户、迁移、备份和四语言测试
│  │  └─ content_delivery_tests.cpp # 内容哈希、starter、提示和外部策略测试
│  ├─ native/content/             # 从网页课程真源确定性导出的只读包
│  ├─ scripts/export-native-content.mjs
│  ├─ scripts/package-native.mjs  # 只复制 EXE/content/config/LICENSE/manifest
│  ├─ scripts/native-product-smoke.py # 真实 Win32 流程、账户隔离、无 TCP/Electron
│  ├─ scripts/sign-internal.ps1  # 内部签名；不修改系统信任库
│  ├─ tests/                      # 内容、打包、安全边界的 Node 测试
│  └─ 工程文件/                   # 本端总工程、后端、路线、审查和本结构
├─ 网页端/                        # 独立网页产品，不被应用端运行时读取
├─ 移动端/                        # 独立移动产品
└─ 备份区/                        # 本轮已校验的源码、文档、旧构建和旧入口归档
```

应用端日常路径是：Win32 UI → 原生服务与本地存储 → Windows 受控工具进程。它不启动 Node、浏览器或服务端口。旧 Electron 源码和历史构建已从产品入口移除，源码和构建归档位于 `备份区/native-integration-20261005/`，用于回滚与审计，不随原生交付目录发布。

Qt UI 目标结构（U1 基础壳、U2 facade、U3 页面骨架已落地）：

```text
应用端/native/ui-qt/
├─ CMakeLists.txt              # 仅 Qt UI 目标，不能把 Qt 依赖传入 codeweave-core
├─ deploy-qt.ps1               # Qt DLL/QML/内容部署与完整性检查
├─ qml/                        # 页面、状态、动画和可访问性描述
├─ facade/                     # QObject 命令/DTO/信号适配层
├─ platform/                   # Qt 窗口、DPI、IME、系统菜单适配
└─ tests/ui_shell_tests.cpp    # 账户、草稿、执行、挑战和数据操作隔离回归
```

`native/ui-qt/` 已在 U1 创建基础骨架，并在 `G:\CodeWeave-qt\mycheck-build` 使用 MSVC + Qt 6.8.3 编译通过。U2 已把课程、正文、starter、账户、草稿、提示、Pending 证据、受控执行和备份/恢复入口接入 `UiShell`；当前 QML 页面代码已合入本地 `main`，学习路径、实战挑战、代码草稿、复习中心、学习分析、账户、编辑器和运行记录页面均能在真实窗口 smoke 中生成截图。QML 只调用 facade，不直接接触文件、Store 或工具路径。部署目录包含 Qt DLL、`platforms/qwindows.dll`、QML imports、content 和配置示例，未启动 Node、浏览器或 TCP 服务。根目录 Win32 EXE 仍是回滚入口，Qt EXE 尚未替换根入口。

U1 复现命令（需要在 Visual Studio Developer Command Prompt x64 中运行，源目录使用 ASCII junction）：

```powershell
cmake -S G:\CodeWeave\app-native-ascii\native -B G:\CodeWeave-qt\build-msvc -G Ninja `
  -DCMAKE_PREFIX_PATH=G:\CodeWeave-prep\qt\6.8.3\msvc2022_64 `
  -DQEWEAVE_BUILD_UI_QT=ON -DCMAKE_BUILD_TYPE=Release
cmake --build G:\CodeWeave-qt\build-msvc --target codeweave-qt-deploy -j 4
```

部署产物位于 `G:\CodeWeave-qt\build-msvc\qt-deploy`。这只是 U1 基础壳验证，不是安装包，也不授权替换根目录 `CodeWeave.exe`。

当前验证入口：在 `应用端` 目录执行 `corepack pnpm test`、`corepack pnpm run check`，再执行 `G:\CodeWeave-qt\verify3.cmd`。合并主线后的 Qt ON CTest 8/8、七页真实窗口 smoke 和懒加载页面性能探针已通过；Qt 工作集/窗口出现、OS 冷启动、同负载可交互就绪、实际屏幕呈现、DPI/IME/UIA 和干净 Windows 仍待验证。历史 `verify.cmd` 仍引用失效旧目录，不能作为当前证据。最新指标见《Qt发布候选清单》。

U4 便携候选由 `scripts/package-qt-release.ps1` 生成，使用逐文件 SHA-256 `manifest.json`，当前树外产物为 `G:\CodeWeave-qt\qt-release-candidate`。该目录只用于验收，不替代根入口，也不进入应用端源码目录。B1 使用自解压当前用户安装器，安装器构建脚本为 `scripts/build-qt-selfextract.ps1`，最终候选为 `G:\CodeWeave-qt\CodeWeaveQt-0.1.0-preview-setup.exe`。


2026-10-05 U2 草稿契约更新：

```text
native/ui-qt/
├─ facade/ui_shell.hpp          # DTO、课程/草稿命令、可信 C++ 会话入口
├─ facade/ui_shell.cpp          # 异步课程、正文、starter、内存编辑

├─ facade/ui_shell_operations.cpp # 提示、Pending 证据、执行、备份/恢复命令
├─ tests/ui_shell_tests.cpp     # QTemporaryDir 隔离的持久化与账户回归
├─ platform/ui_main.cpp        # QQuickView、关闭拦截、真实窗口截图 smoke
├─ qml/Main.qml                # 最小可用布局、课程滚动、草稿/提示/运行入口
├─ CMakeLists.txt               # /MD 核心源码子集、QuickControls2、CTest
└─ deploy-qt.ps1                # Qt 运行库/插件/内容部署，无嵌套内容复制
```

Qt 复用同一份 native/src 核心源码，以 /MD 编译 Qt 所需子集，未引入第二套业务格式。U2 隔离 facade 测试覆盖四语言执行回归、注册/登录/退出、草稿持久化、提示只读、外部证据 Pending、账户隔离和关闭回收；U3/U4 Windows 真实窗口 smoke、便携候选和安装生命周期已通过。窗口证据为 `../evidence/qt-final-window.png`，性能证据为 `../evidence/qt-ui-benchmark-20261006.json`。原生文件选择器已接通；完整输入法、无障碍、DPI、OS 冷启动、同负载课程载入与干净 Windows 仍未验收。编辑/取消代理指标已实测，详情以候选清单为准。

Qt 宿主在 `platform/ui_main.cpp` 负责四语言工具发现，优先读取环境变量、账户数据根下的 `tools.ini`，再读取 PATH；路径先经过核心 `process_contract` 白名单验证后才交给 `UiShell`。QML 不接触工具路径、账户路径或 Store，只调用 `runCode()` 并显示结果。执行错误统一转为可见的取消、超时、输出超限、工具错误或退出码信息，避免空错误码造成“运行失败但没有原因”。
