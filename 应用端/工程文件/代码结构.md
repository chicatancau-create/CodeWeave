# CodeWeave 应用端代码结构

本文只描述应用端。网页端和移动端拥有独立目录、构建链和运行时，不在应用端入口中读取。

## 根目录运行入口

```text
G:/CodeWeave/
├─ CodeWeave.exe                 # Win32 原生回滚入口；运行需要同级 content/ 和 config/
├─ CodeWeave Qt 预览.lnk         # 本机 Qt 预览快捷方式；指向用户安装目录的完整 Qt 部署
├─ content/                      # Win32 入口随包内容
├─ config/                       # Win32 入口的配置标记
├─ 应用端/                       # 应用端源码、脚本、工程文档、证据和历史交付
├─ 工程文件/                     # 项目级基线和跨端工程索引
├─ 工作区/                       # 用户工作区资料，不是构建输出
└─ 备份区/                       # 历史归档、回滚材料和审计证据
```

根目录不再放 Qt 手工复制的 EXE、临时重建脚本或临时说明。Qt 预览不能只靠一个 EXE 运行，它必须和 Qt DLL、QML imports、`platforms/qwindows.dll`、`content/`、`config/` 位于同一部署目录；因此 Qt 运行入口统一使用快捷方式指向 `%LOCALAPPDATA%/Programs/CodeWeave/CodeWeaveQtShell.exe`。

## 应用端目录

```text
应用端/
├─ native/
│  ├─ src/                       # C++ 核心、Win32 壳、账户、内容、执行、学习、备份
│  └─ ui-qt/
│     ├─ qml/                    # Qt/QML 页面和视觉层
│     ├─ facade/                 # UiShell：QML 到原生核心的 DTO/命令边界
│     ├─ platform/               # QQuickView、Windows 对话框、性能探针和入口
│     ├─ tests/                  # Qt facade 隔离回归
│     └─ CMakeLists.txt          # Qt 目标和 CTest 注册
├─ scripts/
│  ├─ export-native-content.mjs  # 从内容真源导出只读内容包
│  ├─ package-native.mjs        # Win32 便携包
│  ├─ package-qt-release.ps1    # Qt 部署目录清单和完整性校验
│  ├─ deploy-qt-preview.cmd     # 将已验证 Qt 构建复制到已安装预览目录
│  └─ 历史本机脚本/              # 2026-10-08 前的重复重建脚本，仅供审计，不是日常入口
├─ dist/
│  ├─ native-final-20261005-r4/ # Win32 历史便携交付
│  └─ 本机Qt副本-20261008/       # 根目录遗留 Qt EXE 的归档副本，不是运行入口
├─ evidence/                     # 可复核测试、性能、窗口截图和矩阵证据
├─ 工程文件/
│  ├─ 总工程/                    # 应用端路线、发布门禁和交接记录
│  ├─ 应用端后端工程.md           # 后端修改规范和接口边界
│  ├─ Qt发布候选清单.md           # Qt 当前状态、门禁和证据索引
│  ├─ 代码结构.md                # 本文件
│  └─ 历史/                      # 过时说明，保留用于追溯，不作为当前命令来源
├─ tests/                        # Node/内容/打包边界测试
└─ README.md                     # 应用端入口、命令和运行约束
```

仓库根目录的 `app-native-ascii/` 是指向 `应用端/` 的 junction，只为 Windows 工具链提供无 Unicode 的 CMake 源路径；它不是第二份源码，禁止在其中创建或编辑文件。根目录的 `.claude/` 是开发工具配置，不属于产品运行时。

## 当前唯一事实源

- Win32 运行基线：`native/src/` + 根目录同级 `content/`、`config/` + `CodeWeave.exe`。
- Qt UI：`native/ui-qt/`，复用同一套 `native/src/` 核心；Qt 构建目录在仓库外 `G:/CodeWeave-qt/`。
- Qt 完整运行目录：`G:/CodeWeave-qt/<候选>/` 或 `%LOCALAPPDATA%/Programs/CodeWeave/`，不能从仓库根目录单独复制 Qt EXE 代替。
- 用户数据：`%LOCALAPPDATA%/CodeWeave/`，不放在源码、构建或交付目录中。
- 旧 Electron/网页端：不属于应用端运行链，历史材料只在 `备份区/` 中按索引恢复。

## 日常命令

Qt 构建和部署使用 `G:/CodeWeave-qt/verify3.cmd` 或 Visual Studio x64 开发环境中的 CMake/Ninja 命令；应用端仓库内的 `scripts/历史本机脚本/` 不作为当前构建入口。新的 Qt 部署必须指定空的输出目录，禁止覆盖正在运行的预览目录。

当前根目录 `CodeWeave.exe` 保留为回滚入口。Qt 的资源、干净系统、IME/UIA 和安装门禁未全部通过前，不替换它，也不把 Qt 副本放回仓库根目录。
