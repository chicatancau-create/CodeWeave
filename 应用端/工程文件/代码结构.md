# CodeWeave 应用端代码结构

更新时间：2026-11-06。应用端外层唯一普通文件为 `启动应用端.lnk`，指向当前完整已安装 Qt 应用。禁止恢复根目录 EXE、content、config、旧启动器或本地历史版本堆放区。

```text
应用端/
├─ 启动应用端.lnk
├─ 项目/
│  ├─ native/
│  │  ├─ src/        # C++23 业务核心与 Win32 壳
│  │  ├─ content/    # 唯一只读内容源
│  │  └─ ui-qt/     # qml、facade、platform、tests
│  ├─ config/        # 不含凭据的配置标记
│  ├─ scripts/       # 导出、打包、部署与测试工具
│  ├─ tests/         # Node 测试
│  ├─ evidence/      # 工程验证证据，不是运行版本
│  └─ workspace/     # 原有本机数据，不上传
├─ 工程文件/
├─ 开发环境/         # Qt SDK、PresentMon、私钥；不上传
└─ 构建产物/qt/current/ # 唯一当前构建；不上传
```

仓库内部 `.local/app`、`.local/prep`、`.local/qt` 为 Windows Qt 工具提供英文路径，分别映射到应用端项目、开发环境、构建目录。不得在 G 盘另建工程或 junction。

日常构建：仓库根运行 `工程文件/工具/构建当前Qt.cmd`；结构验收：`node 工程文件/工具/check-layout.mjs`。内容导出在构建时读取网页端三个版本化课程模块，产品运行不读取网页端源码或用户数据。

正式数据仍位于用户数据目录，旧工作资料保留在仓库 `工作区/`；不得按缓存清理或上传。重复旧构建、旧交付和旧 ZIP 已清理；需要的当前源码使用 Git 备份，不再另留本地历史版本。

源码构建通过不表示已部署替换已安装程序，IME、UIA、干净 Windows 与 Android 设备验收不能由本次结构测试替代。具体范围见根目录 `工程文件/目录整理记录.json`。
