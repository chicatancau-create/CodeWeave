## 1. 当前产品事实

应用端当前入口是 C++23/Win32 原生程序 `G:\CodeWeave\CodeWeave.exe`。运行时不启动 Node、Electron、浏览器、网页服务器或 TCP 端口。发布内容位于程序旁的 `content/`，用户账户和学习数据默认位于 `%LOCALAPPDATA%\CodeWeave` 的账户目录。

当前已接入的后端能力：

| --- | --- | --- | --- |

## 3. Flash 的低复杂度实现原则

Flash 的任务目标是“容易理解、容易审查、容易回滚”，不是提前做高性能重构。除非本文件另有规定，采用以下简单方案：

- 一个功能一个 `.hpp` 和一个 `.cpp`；公共接口写在头文件，行为写在实现文件。
- 使用现有领域类型和 `Result { ok, message }` 风格；不要引入新的框架、依赖、模板元编程或全局单例。
- 服务按直接调用链组织：`main.cpp → Service → Store/Repository`。不增加事件总线、依赖注入容器、插件系统或自动注册机制。
- 每个公共函数先校验输入，再执行文件/进程操作，最后返回结果；失败立即返回，不吞异常。
- 文件写入使用现有原子写工具；不要手写第二套临时文件、锁或 hash 逻辑。
- 先复制相邻实现的写法，再做最小改动。一次只实现一个功能，避免顺手重命名和重构。
- 变量使用完整名称；函数控制在一个责任内；复杂流程拆成 2～4 个直白的小函数。
- 不使用“以后再处理”的 TODO 作为完成标记。确实暂缓时，在工程文件登记路径、原因和验证命令。

所有权规则：

- `main.cpp` 只负责把用户动作转换为服务调用、显示返回消息和管理线程，不直接解析账本格式。

- `ReviewService` 只读，不修改证据和进度。

## 5. 增加后端功能的标准流程

### 5.1 需求登记

先在本文件的“变更登记”末尾写一条记录：功能名、触发入口、数据所有者、输入、输出、失败行为、是否新增文件、验收命令。没有登记不得编码。

### 5.2 选择归属模块

按下面顺序选择已有模块：

1. 账户或权限问题 → `account_service` / `account_store`。
2. 课程正文、提示、starter → `content_repository` / `content_access`。
3. 代码运行或取消 → `execution_service` / `process_runner`。
4. 正式学习事实 → `challenge_service` / `progress_store` / `evidence_store`。
5. 迁移或备份 → `migration_*` / `legacy_import` / `backup_service`。
6. 仅显示汇总 → `review_service`。

只有确认没有合适归属时，才新建模块。新模块必须是一对文件，例如 `bookmark_service.hpp/.cpp`，不得先建空目录或占位脚本。

### 5.3 编写模块契约

新模块头文件必须明确：

- 类型名和命名空间；
- 构造函数依赖；
- 每个公共函数的输入约束；
- 成功返回什么；
- 失败是否写盘、是否创建进程、是否改变状态；
- 线程安全要求；
- 数据文件和版本号；
- 调用方和禁止调用方。

示例：

```cpp
namespace codeweave::feature {
struct Result { bool ok; std::string message; };
class BookmarkService {
 public:
  explicit BookmarkService(std::filesystem::path account_root);
  Result save(std::string_view content_id, std::string_view note);
  Result load(std::string_view content_id, std::string& note) const;
};
}
```

实现要求：先做 ID、长度、UTF-8、路径和权限校验；再读写；写入使用临时文件 + 原子替换；失败保留原文件；重复请求要么幂等，要么明确拒绝。

### 5.4 接入现有应用

按固定顺序接入：

1. 在 `CMakeLists.txt` 加入源文件。
2. 在对应 Service 或 Repository 中实例化，不在多个地方复制状态。
3. 在 `main.cpp` 只增加命令分支和结果显示，不改变控件布局。
4. 在 `native_tests.cpp` 增加正常、失败、边界和重复调用测试。
5. 如需发布内容，先更新 `native/content` 生成器和 hash，再运行内容测试。
6. 更新本文件的模块表、数据格式和回滚说明。

### 5.5 完成判定

新增功能必须同时满足：

- 正常路径可运行；
- 空值、非法 UTF-8、超长输入、重复请求、文件损坏、路径越界有明确结果；
- 账户切换不泄露旧状态；
- 失败不会覆盖旧数据；
- `cmake --build`、CTest、`corepack pnpm test`、`corepack pnpm run check` 与真实 smoke 按影响范围通过；
- 文档、manifest、回滚点已同步。

## 6. 修改已有后端功能

修改前先写“旧行为/新行为/兼容策略”。只允许以下三类：

- **修 bug**：保留正确行为，增加先失败后通过的回归测试。
- **扩展字段**：新增可选字段，旧文件仍可读；写入版本号或迁移步骤。
- **调整规则**：必须说明对旧账户、旧进度、旧草稿和导入文件的影响，并提供回滚。

禁止直接改变：文件名、账本分隔符、operationId 语义、密码 hash 语义、账户目录规则、执行白名单、默认数据根。若必须改变，先增加 `schemaVersion`，实现双读一写或显式迁移，完成旧版样本、损坏样本和回滚测试。

## 7. 删除后端功能或模块

删除前必须确认：

1. `rg` 查明生产调用方、测试调用方、脚本和文档引用；
2. 确认没有用户数据格式依赖；
3. 如果是账本或配置字段，先保留只读兼容读取；
4. 删除代码前先删除调用方和测试，再运行构建；
5. 记录替代方案、回滚点和删除后的验证结果。

禁止因为“暂时不用”删除账户、进度、备份、迁移、恢复、锁或兼容读取代码。无法证明无用的文件保留并登记，不得猜删。

## 8. 临时脚本、测试包和残留清理规范

### 8.1 临时对象必须登记

Flash 创建临时脚本、测试包、日志、截图、测试账户或临时目录时，必须使用：

- 系统临时目录，目录名带任务日期和唯一后缀；或
- 项目约定的 `应用端/项目/evidence/`（只保存正式证据）；或
- `备份区/`（只保存恢复材料）。

在任务开始和结束各记录一次准确路径。不得把临时脚本放到根目录、`native/src`、`scripts` 正式目录或工程文件目录。

### 8.2 删除前的最小检查清单

删除临时对象只检查用户指定的路径及其直接父目录，不扫描全盘。每个路径必须逐一满足：

1. 路径是绝对路径；
2. `resolve` 后仍位于预期临时目录；
3. basename 与登记名称完全相等；
4. 不是符号链接或路径组件异常；
5. 不是正式源码、用户数据、恢复快照、证据或发布产物；
6. 没有正在使用的进程；
7. 删除后再次确认路径不存在。

推荐使用 `Path.resolve(strict=True)` 或 PowerShell `Get-Item -LiteralPath` + `Remove-Item -LiteralPath`。不得使用 `Remove-Item C:\...\Temp\*`、扩展名批量删除、模糊前缀删除或仓库递归删除。

### 8.3 “不确定就保留”规则

如果路径不存在、父目录不匹配、名称不匹配、来源不明、无法确认是否被使用，停止删除并报告准确路径。不要为了清理数量而扩大范围。删除测试账户前也必须确认它位于本次隔离数据根，不能按用户名搜索后批量删除。

### 8.4 正式脚本与临时脚本边界

`应用端/项目/scripts/` 只放可复用、被文档引用、能重复运行且有输入边界的正式工具。一次性脚本用完即删；若以后仍需要，先补 README、参数校验、输出目录、失败清理和测试，再转为正式工具。测试包不是源码，不得放进 Git；正式截图和报告才进入 `evidence/`。

## 9. 数据、安全和并发要求

- 所有用户输入校验 UTF-8、NUL、长度、日期、ID 和路径；拒绝绝对越界路径和符号链接组件。
- 日志不得输出密码、hash、Token、Cookie、个人资料或完整源码。
- 长任务放后台线程，关闭窗口先取消并等待回收；账户切换先阻止新任务并 join 旧任务。
- 账户切换必须清空输出、轨迹、草稿、进度和复习视图；新账户打开失败也不能显示旧账户状态。
- 账本追加必须幂等；相同 operationId 重复请求返回同一事实，不同内容复用 operationId 必须失败。
- 备份先校验源和目标，再生成清单；目标必须在源目录外，跨 Windows 盘符允许，不能覆盖现有目录。
- 导入源只读，先 dry-run 再写入隔离目标；失败保持原活动目录不变。

## 14. Qt/QML UI 替换的后端准备

UI 替换不改变后端事实源。Qt 只是可替换的呈现壳，后端必须先提供稳定、低复杂度、线程安全的命令和状态接口。Flash 不得为了接 Qt 重写现有 Store、账本或执行规则。

### 14.1 后端与 UI 的目标边界

```text
QML 页面 / 输入法 / 动画
        ↓ QObject facade：命令、属性、信号
UI adapter / request generation
        ↓
codeweave-core Service → Store / Repository / ProcessRunner
```

- facade 只能调用已有 Service；不暴露 `std::filesystem`、文件句柄、Windows HWND、账本行格式或密码 hash。
- 状态以可复制的 DTO 返回，错误使用现有 `Result` 语义；QML 不解析错误码字符串来决定业务。
- 长操作（备份/恢复、导入、scrypt、内容扫描）必须通过后台任务和取消令牌执行，完成后带账户 ID/代次回传；旧代次结果直接丢弃。
- 运行输出、轨迹、进度和复习汇总使用只读快照，不能把 Store 引用或裸指针交给 UI。

### 14.2 迁移前必须解决的 UI 线程阻塞

当前 `main.cpp` 的数据管理调用会同步进入递归备份/恢复，`account_register/login/change_password` 在消息处理路径同步调用密码派生。上述阻塞调用链已由源码核验；尚未测实际阻塞时长，不沿用“667 处 IO/秒级假死”的未核实统计。Qt 迁移前应先把这些调用抽成 `BackendTaskService`（一对 `.hpp/.cpp`），实现固定的 `start → progress → cancel → finished` 流程；不改变业务结果、不改变控件、不引入事件总线。每个任务必须有：唯一 task ID、账户/代次、取消状态、错误结果、线程回收和关闭窗口等待规则。

后端执行线程已有 `std::thread + PostMessageW + g_execution_generation` 作为行为参考。Qt 适配层可以使用 `QThread` 或标准线程，但不得让 Qt 类型进入核心库；优先让核心保持标准 C++，UI 层负责 QObject 信号转发。

### 14.3 Windows 平台依赖收口

当前 native/src 中有 15 个文件直接包含 `windows.h`，且密码派生在非 Windows 分支明确失败。这些包含计数含 main 与测试，不是 15 个独立缺陷。Qt-on-Windows 不要求先移走所有 Windows API。按实际重复与 facade 需要逐个考虑以下窄接口，不预建空文件：

- `platform_random.*`：随机数和安全系统调用；
- `platform_process.*`：Job Object、进程暂停/取消、句柄生命周期；
- `platform_paths.*`：数据根、单实例和环境变量；
- `platform_file.*`：原子替换、锁、符号链接和文件属性。

先把新 Qt facade 使用的路径、任务、随机数接口接到这些窄接口；旧模块逐个迁移并保持 CTest 通过。禁止一次性把全部 Windows API 改成抽象层，也禁止为了跨平台删除现有 Windows 安全校验。

### 14.5 后台任务的最小实现契约（已实现并持续扩展）

`BackendTaskService` 为一个可审查的串行后台任务执行器，队列有上限，忙时返回 busy，禁止每个按钮无限创建线程。TaskRequest 至少含 taskId、accountId、accountGeneration、kind 和按值复制的参数；TaskResult 含对应 ID、success/cancelled/error、用户可读信息与只读结果。沿用 app::Result，不给每个模块复制一套 Result 类。

现有 AccountService 有可变 session，不能直接从多个线程调用。账户服务及账户写操作统一在一个后端拥有线程串行执行；GUI 只读返回的 session DTO。执行引擎继续专有工作线程，但传入固定账户 Store/路径快照，统一协调其写入与备份。UI 切换等待旧写入完成或取消后才关闭旧 root/锁；generation 丢弃仅用于呈现，不能撤销已经发生的业务写入。当前 `BackendTaskService` 已支持 `Read/Account/Draft/Evidence/Execute/Backup/Import` 分类，Qt facade 已接入提示读取、外部证据待核验写入、执行和备份/恢复后台入口；文件选择和完整页面交互仍归 U3。

| 操作 | worker 行为 | 取消与一致性 |
| --- | --- | --- |
| 登录/注册/改密 | worker 内校验、派生、提交，凭据短生命周期，不写日志 | scrypt 不支持即时中断时等待安全边界；提交前检查取消，成功写入后不得假报已取消 |
| 备份/恢复/导入 | 逐项枚举/分块复制/清单校验，进度节流最多 10 次/秒 | 暂停冲突写入或取得一致快照；只在安全边界取消；原源保留，只清理任务拥有的目标暂存 |
| 内容/轨迹/复习读取 | worker 读取、校验、分页，返回稳定 DTO | 队列满则合并过时读请求；按 account/course/requestRevision 丢弃旧结果 |
| 草稿保存 | 带 documentId、revision、内容快照，单文档按序原子保存 | 旧保存成功不能把新编辑标已保存；失败保留 dirty，切换/关闭等待保存或明确放弃 |

备份后台化必须防止“边拷贝边自动保存”造成混合快照；覆盖同一数据根的操作只能串行，不通过暂停 GUI 消息循环实现。窗口关闭进入 Closing 状态，拒绝新任务，发取消但保持事件泵，完成后才回收线程与服务；禁止在仍执行的 worker 上从 UI 直接阻塞 join、detach 或强杀线程。PostMessage/queued signal 只携带可管理生命周期的结果，不捕获已析构 HWND/QObject。

回归包括：取消前/提交中/提交后、进度通知失败、关闭时备份、登录中退出、账户切换与运行竞争、损坏草稿、磁盘写入失败、100 次重复开关任务无线程/句柄增长。修复前后记录消息循环延迟，不通过降低 scrypt 成本、跳过 hash 或放宽锁提高成绩。
