REST、校验与 Actuator 健康检查
生产级接口的标配三件

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · IDEA + Spring Boot

【目标】
独立完成带校验的 REST 接口，并使 /actuator/health 返回 UP。

【先备知识】
i1-springboot-starter

【讲解】
@RestController + @Valid + 全局异常：与 H2 同构，Boot 只换装配方式。
Actuator 暴露健康/指标端点；exposure 配置控制可见范围，不宜全开。
日志按包调整级别（logging.level.*），是排错的第一工具。

【例子与反例】
正例：只暴露 health/info/metrics，生产信息不外泄
反例：include 设为星号且无安全防护，环境和 Bean 结构全公开
解释：端点暴露面就是攻击面

【示例代码】
# application.yml
# management.endpoints.web.exposure.include: health,info,metrics
# GET /actuator/health → {"status":"UP"}

【理解要点】
Actuator 把“应用活着吗”变成可查询的端点；健康检查是部署验收的第一条命令。

【跟做】
迁移一个 CRUD 接口并带 @Valid 校验。
引入 actuator，访问 /health 记录返回。
调低某包日志级别，验证排错输出变化。

【独立练习】
独立增加一个自定义 HealthIndicator（检查磁盘或依赖可达性）。

【变式】
多环境配置：dev/prod 两套端口与日志级别。

【项目任务】
I 阶段验收的“启动、接口、健康检查”证据链来自本单元。

【常见错误】
公网暴露全部 actuator 端点
日志级别全局 DEBUG 拖垮性能

【运行方法】
mvn spring-boot:run + curl /actuator/health（本地工程）

【完成标准】
接口带校验、健康端点返回 UP，能解释暴露面控制。

【验收条件】
CRUD 接口校验生效
/actuator/health 返回 UP
日志级别按环境区分

【证据清单】
接口验证输出
health 响应记录
