CSRF、CORS 与请求边界
谁有权发起这个请求

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · 浏览器 + curl

【目标】
独立完成一次跨源请求观察，并解释 SameSite 与 CORS 各自拦截的是哪一类风险。

【先备知识】
j1-auth-session-flow

【讲解】
CORS：浏览器允许跨源读取响应的前提是服务端返回正确的 Access-Control 头。
CSRF：攻击者诱导已登录用户的浏览器向目标站点发请求；SameSite/CSRF Token 是主要防线。
预检（OPTIONS）：非简单请求先问后发，服务端必须显式应答允许的方法与头。

【例子与反例】
正例：跨源 API 只放行已知来源列表并配合凭证策略
反例：Access-Control-Allow-Origin: * 同时 Allow-Credentials: true（浏览器会直接拒绝）
解释：凭证跨源必须指名来源

【示例代码】
# CSRF 与 CORS 观察（本项目 API）：
# 1. 从另一源（如 file:// 或其他端口页面）fetch 本项目 /api/profile
# 2. 观察响应头是否含 Access-Control-Allow-Origin
# 3. 带 Cookie 的跨站表单 POST：被 SameSite=Lax 拦截还是放行？

【理解要点】
CORS 是浏览器对响应的放行规则，CSRF 是“借用户身份发请求”的攻击——两者常被混为一谈。

【跟做】
从不同源页面 fetch 本项目 API，记录预检与响应头。
检查本项目 Cookie 的 SameSite 属性并解释其拦截范围。
构造一个跨站表单 POST 场景（本地两端口），观察是否被拦。

【独立练习】
独立整理“CSRF vs CORS vs XSS”三者的攻击面与防线对照表。

【变式】
为本项目 API 设计一段 CORS 中间件配置，并说明为什么不能写星号。

【项目任务】
请求边界对照表进入 J 阶段验收的安全测试用例清单。

【常见错误】
遇到跨域就加星号响应头
认为 CORS 是服务端安全（它管的是浏览器读取，不是服务端鉴权）

【运行方法】
浏览器跨源页面 + curl -H Origin（真实行为）

【完成标准】
三概念对照表完整，跨源实验有两源实测记录。

【验收条件】
跨源请求预检与响应头记录完整
能区分 CSRF 与 CORS 的拦截对象
SameSite 行为有实测
