打包、文件上传与分页
从 jar 到可交付的单体服务

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · Maven + JDK

【目标】
独立完成 jar 打包与启动、一个上传接口和一个分页接口，全部留下验证记录。

【先备知识】
i2-springboot-rest-actuator

【讲解】
spring-boot-maven-plugin 产出可执行 jar（内嵌容器，java -jar 即起）。
上传需配置大小限制与存储位置；文件名要重命名，防路径穿越与覆盖。
分页参数要有默认值与上限保护，防止 size 超限拖垮数据库。

【例子与反例】
正例：上传文件重命名为 uuid + 原扩展名，并白名单校验类型
反例：直接用原始文件名存盘且无类型检查
解释：上传是文件写入类攻击的入口

【示例代码】
# mvn clean package
# java -jar target/app-0.0.1-SNAPSHOT.jar --server.port=8081
# POST /upload (multipart/form-data)
# GET /tasks?page=1&size=10

【理解要点】
可执行 jar + 外部化配置 = 单体服务的交付形态；上传与分页是业务功能的第一批扩展点。

【跟做】
打包 jar 并在 8081 端口启动，验证接口。
实现 multipart 上传接口，配置大小上限。
给列表接口加 page/size 分页并测边界（page=0、size 超限）。

【独立练习】
独立增加“上传附件 + 列表展示”的小闭环。

【变式】
配置外部化（application-prod.yml + 启动参数），演示不改代码换配置。

【项目任务】
I 阶段验收（迁移 + 新业务功能）的交付物以本单元输出为准。

【常见错误】
jar 内配置写死端口导致多环境无法部署
上传目录放在 jar 解压目录内，升级即丢文件

【运行方法】
mvn clean package + java -jar（本地交付验证）

【完成标准】
jar 启动成功、上传与分页接口验证通过，交付记录完整。

【验收条件】
jar 打包并指定端口启动成功
上传接口受大小与类型限制
分页边界行为正确

【证据清单】
打包与启动日志
上传与分页验证输出
