HTTP 与 REST：请求的一生
方法、状态码与无状态

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · curl + 浏览器

【目标】
独立用 curl 完成一次 GET/POST，并解释状态码、关键响应头与无状态含义。

【先备知识】
java-env-a2（A2 构建与排错）

【讲解】
请求行 = 方法 + 路径 + 版本；响应首行是状态码与短语。
GET 取资源、POST 创建/提交、PUT 幂等更新、DELETE 删除——语义约定即 REST。
2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务端错；看状态码先分类再排查。

【例子与反例】
正例：201 Created 返回体里带新资源地址（REST 语义准确）
反例：所有请求都用 GET 返回 200，错误也返回 200 加错误字段
解释：状态码语义被破坏后，监控与重试策略全部失效

【示例代码】
# 用 curl 观察一次完整请求响应：
# curl -i https://httpbin.org/get
# 请求行：GET /get HTTP/1.1
# 响应状态：200 OK
# 关键头：Content-Type、Set-Cookie、Cache-Control

【理解要点】
HTTP 是无状态协议：会话感来自 Cookie/Token，REST 的语义来自方法与状态码的约定。

【跟做】
用 curl -i 分别请求一个 GET 与 POST 接口，抄下状态行与关键头。
故意请求不存在的路径观察 404，再访问重定向地址观察 301/302。
用 -H 改 Content-Type 提交 JSON，观察 415/400 的差异。

【独立练习】
独立整理一份“本项目会用到的状态码清单”及各自出现场景。

【变式】
用 curl 观察一次 302 跳转全过程（-L 参数前后差异）。

【项目任务】
状态码清单是 G 阶段 Servlet CRUD 接口设计的评审标准。

【常见错误】
把鉴权失败写成 200 + 错误体
混淆 401（未认证）与 403（已认证无权限）

【运行方法】
curl -i（真实网络请求）

【完成标准】
能看懂任意一次请求的响应行与关键头，并说出无状态对会话设计的影响。

【验收条件】
完成 GET/POST 各一次并记录
状态码清单覆盖 2xx—5xx
能解释无状态与会话方案的关系

【证据清单】
curl 输出记录
状态码清单文档
