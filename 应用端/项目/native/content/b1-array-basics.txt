数组遍历与访问
掌握索引、边界与 length 的行为

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
Browser JS 沙箱

【目标】
独立完成数组倒序输出，并解释为什么终止条件是 i < length 而不是 i <= length。

【先备知识】
java-algo-c2（C2 循环累加）

【讲解】
JavaScript 数组索引从 0 开始，最后一个元素是 arr[arr.length - 1]。
循环条件 i < arr.length 恰好遍历全部元素；写成 i <= length 会访问到不存在的 nums[length]。
length 是动态属性：push 之后自动增长，循环中修改它会破坏边界。

【例子与反例】
正例：const n = nums.length; for (let i = 0; i < n; i++) 边界清晰
反例：for (let i = 0; i <= nums.length; i++) 会多跑一轮并输出 undefined
解释：长度为 3 的数组有效索引是 0、1、2，不存在 nums[3]

【示例代码】
const nums = [3, 1, 4, 1, 5];
for (let i = 0; i < nums.length; i++) {
  console.log(i + ": " + nums[i]);
}

【理解要点】
索引从 0 开始、终止条件是 i < length：这两个约定决定了所有数组代码的安全边界。

【跟做】
运行示例，确认输出 5 行“索引: 元素”。
把循环条件改成 i <= nums.length，观察最后多出的 undefined。
改回正确边界，并用单步执行观察 i 的变化范围。

【独立练习】

【变式】

【常见错误】
用 arr[arr.length] 访问最后一个元素
在循环体内 push 导致 length 增长、边界失真
