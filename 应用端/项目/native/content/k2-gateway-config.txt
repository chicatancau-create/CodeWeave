网关与配置中心
统一入口与配置分发

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · Spring Cloud Gateway

【目标】
独立配置网关路由转发到两个服务，并演示一次配置中心下发。

【先备知识】
k1-service-discovery

【讲解】
路由 = 断言（匹配什么请求）+ 目标（lb://服务名）+ 过滤器（改请求/响应）。
鉴权过滤器在网关层统一校验凭证，内部服务信任网关转发的身份头。
配置中心把配置外置，配合刷新端点实现不重启生效。

【例子与反例】
正例：网关统一加 X-User-Id 头，内部服务不再各自解析 token
反例：每个服务自己解析 token 并各自维护密钥
解释：横切逻辑收敛到入口一层

【示例代码】
# gateway 路由配置（application.yml）：
# spring.cloud.gateway.routes:
#   - id: service-b
#     uri: lb://service-b
#     predicates: [ "Path=/api/**" ]

【理解要点】
网关是唯一入口：鉴权、限流、路由集中在这一层；配置中心让多服务改配置不必重启。

【跟做】
起网关，配置两条路由分别指向 a/b 服务。
经网关访问 /api/** 验证转发与响应头。
接入配置中心，改一次配置并刷新端点生效。

【独立练习】
独立实现网关层鉴权过滤器：无凭证返回 401。

【变式】
给路由加 Path 重写，把 /b/api/** 映射到 service-b 的 /api/**。

【项目任务】
网关是 K 阶段验收演示的统一入口，路由表要能解释每一条。

【常见错误】
断言写错导致 404 却去查服务端
网关层透传了不该透传的内部头

【运行方法】
本地起网关（真实转发）

【完成标准】
两条路由可用，鉴权过滤器生效，配置刷新演示成功。

【验收条件】
两条路由转发成功
网关鉴权过滤器生效
配置刷新不重启生效
