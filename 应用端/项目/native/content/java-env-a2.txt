一次构建与一次报错修复
故意制造并修复一次构建错误，留下排错记录

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · Maven

【目标】
完成一次成功构建，并故意制造一次构建错误后修复它，形成排错记录。

【先备知识】
java-env-a1

【讲解】
读报错只看第一行：它通常直接指出缺失的类、符号或版本。
构建错误分为依赖类（下载失败、版本冲突）与代码类（语法、符号缺失）。
排错记录的价值随项目增长：下次遇到同样报错直接查表。

【例子与反例】
正例：记录报错原文 + 原因 + 修复三段
反例：只写“改好了”
解释：复现与教学价值都在原文里

【示例代码】
# 构建排错记录模板
# 命令：mvn compile
# 报错原文：（粘贴第一行错误）
# 原因分析：
# 修复步骤：
# 复验结果：BUILD SUCCESS

【理解要点】
排错能力 = 完整复制报错 + 定位首个错误 + 记录修复，三者缺一不可。

【跟做】
用模板创建 build-trouble-log.txt。
删掉一个分号触发编译错误，按模板填写并修复。
再制造一次依赖版本错误（如不存在的依赖）观察差异。

【独立练习】
独立完成“成功构建 + 报错修复 + 记录”完整闭环。

【变式】
把一次运行时异常（如数组越界）也按模板记录，比较与编译错误的差异。

【项目任务】
排错记录模板沉淀为项目的 docs/trouble-shooting.md。

【常见错误】
只截图不复制文本，无法检索
同时改多处导致无法定位真正原因

【运行方法】
mvn compile（真实 Maven 环境）

【完成标准】
排错记录含报错原文、原因、修复步骤与复验结果。

【验收条件】
至少一次 BUILD SUCCESS 复验
排错记录四要素齐全

【证据清单】
构建日志片段
排错记录文件
