Git 分支与提交纪律
用分支完成一次功能提交并回看历史

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · Git

【目标】
在独立分支上完成一次提交，并用 git log 解释提交历史。

【先备知识】
java-env-a1

【讲解】
分支让实验性改动不污染主干；合并前可以随时丢弃。
提交信息用“类型: 描述”格式（docs:/fix:/feat:），便于生成变更记录。
git log --oneline 是回看历史最快的方式。

【例子与反例】
正例：feat: 增加联系人添加功能
反例：update / 修改 / 111
解释：无意义信息让回溯失效

【示例代码】
# Git 操作清单
# git switch -c feature/env-notes
# git add README.md
# git commit -m "docs: 记录环境清单"
# git log --oneline

【理解要点】
小步提交 + 规范信息，是可回溯开发的最小纪律。

【跟做】
创建 feature 分支并提交一项改动。
切回主分支确认改动不在，再合并回来。
用 git log --oneline 解释最近三条提交。

【独立练习】
独立完成“分支 → 提交 → 合并 → 回看”全流程。

【变式】
制造一次冲突（两个分支改同一行），手动解决并提交。

【项目任务】
后续每阶段的项目都在分支上开发，主干保持可运行。

【常见错误】
在 main 上直接做大改动
一次提交混入多个不相关改动

【运行方法】
git 命令行（真实仓库）

【完成标准】
仓库里有一条 feature 分支的合并记录，能口述每条提交内容。

【验收条件】
完成分支创建与合并
提交信息符合类型前缀规范

【证据清单】
git log 输出
分支合并记录
