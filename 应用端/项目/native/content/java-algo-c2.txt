循环累加与复杂度
用循环求和，数一数执行了多少轮

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
教学运行器 · Java 子集

【目标】
独立完成 1—100 累加，并用轮次分析说明 O(n)。

【先备知识】
java-algo-c1

【讲解】
循环执行 100 轮，每轮一次加法 → 时间复杂度 O(n)。
高斯公式 n(n+1)/2 是 O(1) 的对照：同样是求和，复杂度可以差一个数量级。
变式只改循环边界或步长，轮次分析要先于运行。

【例子与反例】
正例：先说“循环 100 轮，预计输出 5050”再验证
反例：直接运行看答案，说不出轮次
解释：复杂度思维来自运行前分析

【示例代码】
public class Main {
    public static void main(String[] args) {
        int total = 0;
        for (int i = 1; i <= 100; i++) {
            total += i;
        }
        System.out.println(total);
    }
}

【理解要点】
循环次数决定复杂度：n 轮就是 O(n)，能在写之前估计运行规模。

【跟做】
预测 1—100 累加结果并运行验证（5050）。
改成只累加偶数，先写轮次分析再运行。
把上限改成 1000000，观察运行是否仍然瞬间完成。

【独立练习】
独立完成 1—n 求和并推导 n=1000 时的轮次与结果。

【变式】
求 1—100 中所有 3 的倍数之和（循环 + 条件）。

【项目任务】
为通讯录项目统计功能提供“遍历计数”的实现原型。

【常见错误】
循环边界差一（< 与 <=）
在循环体内重复声明变量

【运行方法】
运行按钮（教学运行器支持 for + total 子集）

【完成标准】
运行前能给出轮次与预测输出，运行后一致。

【验收条件】
预测与运行输出一致
能用一句话说明 O(n) 的含义
