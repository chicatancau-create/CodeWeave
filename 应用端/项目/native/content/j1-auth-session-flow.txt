认证与授权：Session、Token 与边界
登录态如何在请求间维持

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · curl + 本项目 API

【目标】
独立完成一次完整登录流程观察，并解释 Cookie 会话与 Token 方案的取舍。

【先备知识】
i2-springboot-rest-actuator

【讲解】
登录成功后服务端颁发凭证：Cookie+Session 存服务端，JWT 把状态签名进令牌。
HttpOnly 阻止 JS 读 Cookie，SameSite 缓解 CSRF；Token 常放 Authorization 头。
会话必须有过期与登出失效：只颁发不回收等于门永不锁。

【例子与反例】
正例：本项目登出后旧 Cookie 立即失效（服务端删除会话）
反例：Token 永不过期且无法吊销，泄露即永久失控
解释：凭证生命周期是安全设计的一部分

【示例代码】
# 认证流程观察（真实服务或本项目的 /api/auth/*）：
# 1. POST /api/auth/login（错误密码）→ 401
# 2. POST /api/auth/login（正确密码）→ Set-Cookie: code_canvas_session=...
# 3. GET /api/auth/me（带 Cookie）→ 用户数据
# 4. GET /api/auth/me（不带 Cookie）→ {"data":null}

【理解要点】
认证回答“你是谁”，授权回答“你能做什么”；会话是两者的载体，过期与失效同样重要。

【跟做】
用 curl 走完本项目 4 步登录流程并记录状态码与 Cookie。
观察登录前后的差异：哪些接口开始返回数据。
画出 Session 方案与 JWT 方案的时序对比。

【独立练习】
独立整理一张“未登录 / 登录 / 登出”三态下各接口行为的验证表。

【变式】
对比 JWT：解码一段真实 JWT 的 header/payload（不签名验证），说明为何不能放敏感信息。

【项目任务】
J 阶段验收（验证未登录、无权限和异常请求）的测试用例清单来自本单元。

【常见错误】
把用户敏感信息放进 JWT payload（base64 不是加密）
前端只在 UI 隐藏按钮而不做后端鉴权

【运行方法】
curl -i + 本项目 /api/auth/*（真实 API）

【完成标准】
三态验证表完整，能解释两种会话方案的取舍。

【验收条件】
四步流程状态码记录完整
未登录/登出后受保护接口不可访问
能对比 Session 与 JWT

【证据清单】
curl 输出记录
三态验证表
时序对比图或文字
