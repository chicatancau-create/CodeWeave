XSS 防御与输入净化（沙箱可执行）
为什么转义发生在输出侧

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
Browser JS 沙箱

【目标】
独立实现 HTML 转义函数，在沙箱中验证恶意载荷被净化，并解释三条 XSS 防线。

【先备知识】
b1-array-basics
d3-dom-events

【讲解】
存储型/反射型/DOM 型 XSS 的共同点：不可信数据进入了代码执行环境。
输出侧转义（& < > " '）让标签变成普通文本；textContent 天然安全，innerHTML 危险。
防线叠加：CSP 响应头、HttpOnly Cookie、框架默认转义——任何一层都不能单独兜底。

【例子与反例】
正例：escapeHtml 把 <img onerror=...> 变成不可执行的文本实体
反例：把用户输入直接 innerHTML 或拼进模板
解释：innerHTML 会解析并执行标签内的事件

【示例代码】
function escapeHtml(text) {
  const map = { "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" };
  return text.replace(/[&<>"']/g, (ch) => map[ch]);
}
const payload = '<img src=x onerror="alert(1)">';
console.log("原始长度:", payload.length);
console.log("净化后:", escapeHtml(payload));
console.log("净化后仍含标签?", escapeHtml(payload).includes("<img"));

【理解要点】
XSS 的根因是“数据被当成代码执行”；转义发生在输出侧，且必须按输出上下文选择转义规则。

【跟做】
在沙箱运行示例，观察净化前后差异。
构造一个含 onclick 的载荷，验证转义后不再含活标签。

【常见错误】

用正则删标签当“过滤”，属性事件仍可逃逸
