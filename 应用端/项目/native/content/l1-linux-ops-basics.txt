Linux 交付基础：进程、端口与日志
在服务器上找到并管住你的应用

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · Linux 服务器

【目标】
独立在 Linux 上部署 jar 并完成“进程—端口—日志”三步验证，排掉一个人为故障。

【先备知识】
i3-springboot-package-upload

【讲解】
ps/kill 管进程；ss/netstat 查端口占用；nohup 或 systemd 让应用后台常驻。
环境变量与启动参数决定多环境行为，不要把配置烧进 jar。
日志要落盘、要轮转、要能 grep；控制台日志在断开终端后就没了。

【例子与反例】
正例：systemd 托管 + Restart=always，崩了自动拉起
反例：ssh 里裸跑 java -jar，断开连接应用即死
解释：进程托管方式决定可用性

【示例代码】
# 在 Linux 服务器上执行：
# ps -ef | grep java          # 找进程
# ss -tlnp | grep 8080        # 谁在监听端口
# tail -f app.log             # 跟踪日志
# journalctl -u myapp -n 50   # 服务日志

【理解要点】
交付应用的三连问：进程在吗、端口通吗、日志说什么——90% 的部署问题止于这三步。

【跟做】
scp 上传 jar，用 nohup 或 systemd 启动。
三步验证：进程、端口、日志各留一条输出。
故意改错端口配置制造启动失败，按日志定位并修复。

【独立练习】
独立编写一个 systemd service 文件管理应用。

【变式】
配置 logrotate 让日志按天轮转并保留 7 天。

【项目任务】
本单元是 L 阶段验收（干净环境启动、测试、排错）的最小执行手册。

【常见错误】
防火墙没开端口误判应用没起
root 直接跑应用（最小权限原则失效）

【运行方法】
真实 Linux 服务器或 WSL（不能由浏览器替代）

【完成标准】
三步验证齐全，人为故障在 10 分钟内按日志定位修复。

【验收条件】
jar 在服务器常驻运行
三步验证输出齐全
一次故障按日志定位修复

【证据清单】
三步验证输出
故障排查记录
