注册发现与服务调用
两个服务如何找到彼此

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · Spring Cloud + 注册中心

【目标】
独立运行注册中心 + 两个服务，A 通过服务名成功调用 B 并解释解析过程。

【先备知识】
i3-springboot-package-upload

【讲解】
服务启动时把“服务名 + 地址”注册到注册中心；停机或心跳失败会被摘除。
调用端用服务名发起请求，客户端负载均衡从实例列表选择一个。
本地实验可用 Nacos/Eureka/Consul 任一实现，关键是理解注册与发现两条链路。

【例子与反例】
正例：启动 B 的两个实例，A 调用时日志显示轮询分发
反例：A 把 B 的 IP 写死在配置里，B 换端口即断
解释：硬编码地址消灭了弹性

【示例代码】
# 服务 A 与 B 都向注册中心注册：
# spring.application.name=service-a / service-b
# 服务 A 通过服务名调用 B（负载均衡由调用端解析）：
# GET http://service-b/api/tasks

【理解要点】
注册中心把“IP:端口”换成“服务名”：实例可以随起随停，调用方无感知。

【跟做】
起注册中心，依次启动 service-a/service-b 并确认注册成功。
A 实现 /call-b 接口经服务名转发。
再起一个 B 实例，观察调用在两个实例间分布。

【独立练习】
独立实现 B 的健康检查端点，停掉一个实例观察摘除时间。

【变式】
给调用加超时与 fallback（失败返回默认值而不是白屏报错）。

【项目任务】
双服务 + 注册中心是 K 阶段验收（运行两个服务和一个网关）的前半程。

【常见错误】
服务名大小写或连字符不一致导致找不到实例
本机多实例端口冲突没发现，误判为注册失败

【运行方法】
本地起注册中心与两个 Spring Boot 服务（真实多进程）

【完成标准】
双实例负载均衡可复现，停机摘除有实测时间记录。

【验收条件】
两个服务注册成功
按服务名调用打通
多实例轮询可观察
