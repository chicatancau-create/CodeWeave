开发环境清点
把工具链逐个清点并留下版本记录

【来源】
CodeWeave 内置课程快照；学习进度由当前账户证据决定。

【运行环境】
外部环境 · 终端

【目标】
独立完成 JDK / Node.js / Maven / Git 的安装验证，并留下可复现的版本记录。

【先备知识】
一台可用电脑
管理员权限

【讲解】
版本输出是环境的第一手证据：java -version、node -v、mvn -v、git --version 各有一条。
JAVA_HOME 与 PATH 是 Java 工具链最常见的两类配置问题。
把安装过程写进 README，重装系统时照着做即可复原。

【例子与反例】
正例：把每条 --version 输出原文贴进 README
反例：只写“已安装 JDK”没有版本号
解释：无法排查“换台机器就跑不起来”的问题

【示例代码】
# 环境检查清单
# java -version
# node -v
# mvn -v
# git --version

【理解要点】
环境问题的第一手证据是版本输出；先清点，再谈开发。

【跟做】
依次运行四条版本命令并截图或复制输出。
发现任一工具缺失时按官方文档安装后重跑。
在项目 README 里记录版本与安装来源。

【独立练习】
独立完成四件工具的清点，输出一段带版本号的记录。

【变式】
故意把 JAVA_HOME 指向错误路径，观察 mvn 报什么错并恢复。

【项目任务】
这份清单是 A 阶段项目（后续所有 Java 工程）的环境前置说明。

【常见错误】
只检查了 java 没检查 JAVA_HOME
Git 没配置 user.name / user.email 就开始提交

【运行方法】
在真实终端执行版本命令（浏览器无法替代）

【完成标准】
README 中有四条版本输出与安装来源记录。

【验收条件】
四条版本命令全部成功执行
README 含版本号与安装来源

【证据清单】
终端版本输出原文
README 环境章节
