## 修订说明：本轮纠正的实施盲区

以下不是可选优化，而是落地前必须纳入的约束：

1. **快照边界扩展到附件。** 当前 `server/content/asset.mjs:129-132,162-232` 从实时资料库读取附件，并以路径、大小、mtime 生成 ETag；`compiler.mjs:990-1016` 的 bundle 核心也未纳入附件内容哈希。因此现状不能声称“同一 bundle 的附件不可变”。本方案改为发布时登记并固化附件，按内容哈希校验。
2. **读取权限与发布权限分离。** 当前 `server.mjs:460-476,539-560` 对 `/api/content/sync` 只做内容读取准入；真实发布会写源清单和快照。开放三端前必须增加服务端发布者授权，不能依赖隐藏按钮。
3. **发布任务需要可恢复终态。** 当前任务结束时 `snapshot.mjs:224-230` 清空活动任务，而 `server.mjs:563-568` 只查询活动任务，完成后会返回 404。前端轮询必须与服务端终态留存、重启恢复一起设计。
4. **远程实例不能沿用开放注册和自助抢占拥有者。** 当前注册入口对所有请求开放（`server.mjs:863-866,933-977`），未绑定资料库允许已登录账户读内容（`owner.mjs:89-98`），且已登录账户可提交拥有者绑定（`server.mjs:604-617`）。必须增加初始化、邀请和拥有者恢复流程。
5. **旧课映射必须同时改变目录和进度解析。** 当前 `src/content/adapter.ts:358-377` 始终追加 legacy 课程；只填写 `legacy-map.json` 而不改适配器会重复展示。只有已审核的一对一 `exact` 映射才能成为别名/重定向，不再生成第二张独立课程卡；partial/split/merge/unmapped 必须继续隔离。
6. **“原子切换”不等于跨资源 ACID 事务。** 文件快照、活动指针、源清单、数据库和资料库写回跨越不同存储，只能使用日志、哈希、幂等和可恢复状态机保证一致，不使用夸大的全局事务表述。

复核时还确认了必须精确施工、不能误修的边界：

- `mapVersion` 与 `legacyMapHash` 已进入 bundle 核心（`compiler.mjs:990-1016`）；缺的是**catalog 输出、adapter 去重、canonical ID 解析和逐类迁移**，不是“映射完全没进快照”。
- 现有发布事务已有持久 journal 和对账代码（`content/index.mjs:99-185`），但对账由 `status()` 或真实 `sync()` 懒触发，且 `candidate` 分支假定 current 尚未切换（`index.mjs:121-127,142-150,217-219,288-290`）。因此不能只补持久 job 关联，也不必重写全部事务；必须先修 candidate/pointer 崩溃窗、强制启动对账，再关联 job 终态。
- 现有二次复核只登记正文、教学单元、练习和规则（`compiler.mjs:1092-1097`）。精确审批必须把附件、两份映射和所有影响候选的清单/编译配置纳入完整输入指纹，不能只追加附件哈希。
- legacy outbox 必须按事实来源的 `bundleId + aliasVersion` 解析，不能在上传时改用 current，否则跨版本映射变化会把旧事实归到另一门课。
- 当前 `vaultMatches` 只用于状态展示，未参与内容、进度或写回授权（`learning/index.mjs:70-82,118-152`）。`owner.vaultId` 与当前资料库不匹配时必须统一 fail-closed，不能由 owner 身份或 `publicContent=true` 放行。

## 0. 强制门禁与实施顺序

以下门禁是方案的一部分，不是可选建议。除用户明确批准的真实发布、数据迁移或部署外，门禁开发均可先在隔离 fixtures 和临时运行根中完成。

| 门禁 | 最迟完成时点 | 必须关闭的问题 | 未通过时的硬限制 |
| --- | --- | --- | --- |
| G0 现场与契约基线 | 任何实现前 | 固定源码基线、隔离真实数据、确认未提交资产归属、修正文档漂移 | 不操作真实资料库和账户 |
| G1 发布安全 | **首次真实发布前** | 发布分权、附件固化、完整审批输入、提交幂等、持久 job、candidate/pointer 崩溃窗、强制启动对账和前端终态轮询 | 只允许 dry-run，不得切换 current |
| G2 内容身份 | **任何非空 legacy 映射启用前** | 版本化 alias、目录去重、旧选择/深链/进度/草稿解析和冲突保留 | 空映射基线可试点，非空映射不得发布 |
| G3 三端只读一致 | Qt/Android 接入验收前 | bundle 固定、条件请求、整包校验、账户域缓存和契约能力协商 | 不宣称三端同版本，不开放写入 |
| G4 远程安全 | **监听地址改为非 loopback 或经反向代理暴露前** | 一次性初始化、邀请、未绑定默认拒绝、owner/vault 不匹配拒绝、owner 恢复、持久会话、HTTPS 和逐接口授权 | 仅允许 `127.0.0.1` 本机试点 |
| G5 学习事实与写回 | 任何跨端写入前 | 事务存储、游标/幂等/冲突、来源 bundle alias、owner/vault 不匹配拒绝、账户切换、迁移演练、单写者和备份恢复 | 学习数据保持本地，资料库不正式写回 |

## 1. 推荐结论

采用 **“一个统一数据服务 + 三端适配器 + 本地缓存/离线队列”**。

- 复用 `网页端/项目/server` 作为统一服务起点，不另建第四套产品或第二套内容编译器。
- 原始资料库是**新正式内容**的权威来源；旧内置课程仅是过渡期只读兼容源，不能形成长期双权威。
- 三端只消费经过校验的不可变快照，不直接读取整个资料库；快照必须同时固定正文、练习、规则和引用附件的内容哈希。
- 网页端继续同源调用；应用端增加**用户主动开启**的在线同步模式并保留原生离线能力；移动端只走 HTTPS API。
- 第一阶段只打通只读内容；学习事实同步和资料库写回放在后续独立阶段。
- 内容阅读、内容发布、学习事实写入和资料库写回分别授权；默认最小权限。
- 在线模式下，资料库写回只能由统一服务协调；禁止 Node 与 Qt 两套写回实现并发修改同一资料库。
- 一个数据根只允许一个统一服务实例，但服务进程生命周期必须独立于任一客户端；客户端退出不等于服务数据已提交或已同步。

不推荐三种捷径：

1. 三端直接共享 `工作区/` 文件——移动端不可用，且权限、锁、冲突和路径泄露无法控制。
2. 把 14.74 GB 原库直接打包到三端——包含非发布内容、历史资料及依赖，边界不可接受。
3. 为应用端和移动端各复制一套编译/写回逻辑——会继续扩大 schema 和进度口径漂移。

## 2. 目标、假设与非目标

### 2.1 目标

- 同一个 `vaultId + bundleId` 在网页端、应用端、移动端代表同一份正式内容。
- 同一账户的进度、证据、打卡、挑战和复测记录能够跨端恢复，重复同步不产生重复事实。
- 断网不丢草稿；重连后可识别冲突，不以“最后写入”静默覆盖。
- 私有正文、账户、路径和正式学习记录不进入公共内容包。
- 任一发布或同步失败，都能继续使用上一份有效内容并完成恢复。
- 服务端或任一客户端升级时，能通过契约版本和能力协商保持可诊断的兼容性；不支持时停止写入而不是静默丢字段。
- 回滚不仅恢复旧版本，还必须保留切换后产生的新学习事实和草稿。

### 2.2 默认假设

- 初期为私人、自托管、单服务实例，暂不承诺公网、多节点或多人高并发。
- 服务端宿主不在线时，网页和移动端只能使用已缓存内容；不得把本地缓存说成最新服务端状态。
- 应用端默认离线；只有用户明确配置并开启后才连接统一服务。
- 移动端第一阶段只做登录、目录、正文和缓存，不在本方案中承诺移动代码执行。
- 新内容先以当前 U01 试点验收；旧内置课程在过渡期保留并显式标记，不猜测合并。
- 首个实例默认不开放自由注册；账户初始化、邀请和拥有者指定属于部署配置，不由普通客户端自行决定。

### 2.3 非目标

- 不全量审校所有资料正文，不把第三方镜像和历史归档自动发布。
- 不重写现有 React/Qt 页面，不替换原生执行引擎。
- 不在本阶段部署生产环境、迁移真实账户或执行正式写回。
- 不为“统一”而强行统一各端视觉和执行能力。

## 3. 总体架构

```text
                    原始资料库（唯一内容权威）
                    工作区/全栈工程师学习资料库
                               │
                  分批投影 / 来源卡 / 规则 / 稳定 ID
                               │
                    CodeWeave/content-manifest.json
                               │
                    compile + dry-run + 人工审批
                               │
                不可变正文快照 + 内容寻址附件 + current 指针
                               │
        ┌──────────────────────┴──────────────────────┐
        │             统一数据服务（现有 Node 服务演进）           │
        │ 初始化/邀请 │ 阅读/发布分权 │ 内容 API │ 学习事实 │ 同步/写回 │
        └───────────┬───────────────┬───────────────┬───────────┘
                    │               │               │
              同源 HTTPS      可选 HTTPS       HTTPS
                    │               │               │
              网页端 React      应用端 Qt/C++    移动端 Android
              内存详情缓存       原生内容包回退     Room/本地缓存
              localStorage草稿  本地账本+outbox    离线队列
                    │               │               │
              浏览器执行能力     本地原生执行引擎    后续再评估执行
                    │               │               │
              只上传用户确认的    只上传用户确认的    只上传用户确认的
              学习证据，不上传    学习证据；不自动    学习证据
              任意缓存           上传源码/变量
```

**核心边界：** 内容快照可以缓存，正式学习事实以服务端同步日志为准；本地缓存永不反向覆盖原始资料库。

## 4. 数据权威与分类

| 数据类别 | 权威来源 | 三端可见形式 | 允许写入 |
| --- | --- | --- | --- |
| 原始课程正文 | 原始资料库白名单来源 | 编译后的发布正文 | 只在原库修改，经生成器与复核进入投影 |
| 发布投影、规则、来源卡 | 资料库 `CodeWeave/` | 不作为客户端任意文件入口 | 生成器/受控编辑；稳定 ID 不可清空重建 |
| 正式内容快照 | 统一服务 `content/snapshots` 与附件存储 | catalog/detail/exercise/asset | 正文与全部引用附件经清单和哈希固化后才可切换 current；跨文件用可恢复发布状态机 |

| 账户与会话 | 统一服务 | 当前用户与安全会话 | 服务端校验；客户端不提交 userId 取得越权 |

| 代码与项目草稿 | 本地优先，用户选择同步后的服务端副本 | 编辑器与冲突视图 | `baseRevision` 冲突检测，不静默覆盖 |
| 内容/账户缓存 | 各端本地 | 离线视图 | 可失效/重建，不冒充正式事实 |
| 执行输出、变量与轨迹 | 当前执行端本地 | 当前工作台 | 默认不离开设备；只暂存用户明确选择的证据 |

## 5. 契约设计

### 5.1 复用现有接口

以下接口是当前兼容起点，**不代表现有实现可以直接远程开放**：

| 能力 | 接口 | 复用条件 |
| --- | --- | --- |
| 认证 | `POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me` | 登录可复用；注册默认关闭，仅初始化/邀请流程开放 |
| 内容状态与目录 | `GET /api/content/status`、`GET /api/content/catalog` | 保持阅读权限；增加版本协商、分页和缓存规则 |
| 正文与练习 | `GET /api/content/lessons/{id}`、`GET /api/content/exercises/{id}` | 增加 bundle 固定和版本不匹配处理 |
| 附件 | 旧 `GET /api/content/asset` 仅作本机兼容；新契约使用 `GET /api/content/assets/{assetId}?bundleId=...` | 对外只暴露 opaque assetId；字节只读已发布 CAS 对象，不再接受源路径 |
| 内容同步 | `POST /api/content/sync`、`GET /api/content/sync/{jobId}` | dry-run/真实发布均要求发布权限；真实发布绑定精确审批；任务终态持久化，普通读者无发布诊断权限 |
| 拥有者与进度 | `GET /api/learning/status`、`GET /api/learning/vault-progress` 及现有 owner 接口 | 现有 `POST /api/learning/owner` 不再承担远程首次认领；初始化、转移、解绑和恢复分别授权并撤销相关会话 |
| 证据写回 | 现有 evidence 暂存、预览、提交、回滚、导出和事务接口 | 暂存与正式写回分权；提交前检查契约版本、预览指纹和操作归属 |

### 5.2 必补的增量契约

| 新能力 | 建议契约 | 目的 |
| --- | --- | --- |
| 固定内容版本 | catalog/detail/exercise/asset 接受 `bundleId`；响应统一返回实际 `bundleId` 与 `manifestHash` | 防止目录、正文、练习和附件跨版本混读 |
| 条件请求 | catalog/asset 支持 `If-None-Match`/304，且先鉴权再命中缓存 | 降低三端轮询成本，不让 304 绕过权限 |
| 固化附件 | `GET /api/content/assets/{assetId}?bundleId=...` | 按清单与内容 SHA-256 读取，不再访问实时资料库 |
| 桌面离线包 | `GET /api/content/bundles/{bundleId}/manifest` 与 `.../payload` | 下载完整 JSON 快照、包内相对路径、文件清单和 SHA-256 |
| 增量拉取 | `GET /api/sync/pull?cursor=<opaque>&limit=<n>` | 按账户游标获取变化、删除 tombstone 和下一游标 |
| 幂等推送 | `POST /api/sync/push`，带 `Idempotency-Key` | 重试不产生重复事实，返回 accepted/duplicate/conflict |
| 同步状态 | `GET /api/sync/state` | 提供服务端游标、syncEpoch、账户域和待处理冲突数量 |

#### 5.2.1 固定 bundle 的读取上下文

1. catalog 必须返回 `serviceInstance`、`vaultId`、`bundleId`、`manifestHash`、契约版本、能力集合和该版本的 `legacyAliases`。
2. 新三端从一次 catalog 建立读取上下文，后续 detail、exercise、asset、manifest/payload **必须携带同一 bundleId**。服务端能读取仍保留的指定 bundle；不得把指定旧 bundle 的请求静默改发到 current。
3. 旧调用暂时允许省略 `bundleId`，仅表示“本次请求读取当前版本”；响应仍必须给出实际版本。客户端一旦发现同组响应版本变化，必须丢弃整组内存/缓存结果并从 catalog 重建，不能把 A 目录与 B 正文拼在一起。
4. 指定 bundle 已切换且服务端不允许继续读取时返回 409 `content_bundle_changed`；已确认退役返回 410 `content_bundle_retired`；bundle 内对象不存在返回 404。三者都不能隐式回退到实时资料库或另一 bundle。
5. catalog 的 ETag 至少绑定 `vaultId + bundleId + manifestHash + 表示版本`；附件 ETag 使用完整内容 SHA-256。所有 304 都必须在认证、实例/资料库准入和资源权限通过之后返回。
6. 正文中的附件链接由服务端按当前 bundle 重写为 assetId URL。离线 manifest 只含规范化包内相对路径，API、job、冲突、日志和客户端缓存元数据均不得暴露源绝对路径。

#### 5.2.2 附件固化、校验与生命周期

发布编译器必须从正式发布正文实际引用的附件生成稳定排序的 `core.assets`，每项至少包含：

```json
{
  "assetId": "对外不透明且不含路径的ID",
  "packagePath": "assets/包内相对路径",
  "sha256": "64位小写十六进制",
  "size": 12345,
  "contentType": "image/png"
}
```

- `assetId` 采用确定性不透明值：`asset-` + `SHA-256(规范化 packagePath + NUL + 内容 sha256)` 的前 32 个十六进制字符。它不包含源路径，也不依赖当前 bundleId，便于同内容跨版本复用；包内路径变化会生成新 ID。
- 源路径只留在服务端暂存映射中，不进入公开 manifest。`core.assets`、映射版本和附件清单摘要必须参与 `bundleId`。发布前的完整二次复核必须覆盖正文、教学单元、练习、规则、附件、`legacy-map.json`、`topic-id-map.json` 以及其他影响候选的清单/编译配置；不能只在现有四类 `sourceHashes` 后追加附件（`compiler.mjs:1092-1097`）。
- 发布时先对解析后的真实路径做根目录 containment、普通文件、类型和大小检查，再复制到本 attempt 的暂存区；对**已复制字节**计算 SHA-256。缺文件、越界、链接/junction 逃逸、类型/大小不符、哈希与审批不符均阻断。
- 校验通过后写入 `content/assets/<sha256>` 内容寻址存储。临时对象验证后原子落位；复用既有对象前也要验证，不能因“同名文件已存在”直接信任。
- 所有正文、练习和附件对象完整可读后，才允许进入唯一 current 切换点。任一步失败均保留旧 current、旧目录和旧附件。
- asset GET 只从 CAS 读取；首次使用或读取时校验对象，损坏返回稳定的 `asset_corrupt` 并阻断坏字节，不回源补读。
- GC 以 bundle 清单为引用根，至少 pin 住 current、可回滚包、正在发布/下载的包和明确支持的离线包。共享附件只有在所有引用根解除并经过可恢复标记—清理后才能删除；不得只按 mtime 或“最近三代”直接删。
- 哈希用于完整性与损坏检测，不代替发布者认证、传输 TLS 或权限判断。

#### 5.2.3 精确审批、发布幂等和持久 job

真实发布采用“**dry-run 产生候选 → 审批精确候选 → 激活同一候选**”两段式：

1. dry-run 请求带 `Idempotency-Key`，完成后得到 `candidateBundleId + manifestHash + approvalId`。审批绑定 `serviceInstance + vaultId + candidateBundleId + manifestHash + 来源/投影版本 + 附件清单哈希 + 两份映射哈希 + 编译配置指纹`，且只能消费一次。
2. 真实发布请求带独立操作 ID、`approvalId`、`expectedBundleId` 和 `expectedCurrentBundleId`，并继续使用 `Idempotency-Key`。正文、附件、规则、两份映射或编译配置任一变化均返回 409 `approval_stale`，不得换一个候选继续沿用旧审批。激活前必须重新计算并比对完整审批输入指纹，或完整重编译后比对 `candidateBundleId + manifestHash`；只复核现有 volumes/units/exercises/rules 不足以证明候选未变。
3. 在工作开始前持久化发布意图和规范化请求指纹；同一发布者重复提交同键同请求返回同一 job，同键不同请求返回 409 `idempotency_conflict`。响应丢失后的重试不得第二次消费审批。
4. 单实例互斥不是崩溃恢复。每次执行带 `attempt/fencing` 代次；只有当前代次能更新 job、journal 和活动指针。current 切换使用 `expectedCurrentBundleId` 前置检查，旧 attempt 的迟到写入必须被拒绝。
5. “候选已生成”“已审批”“已成为活动版本”分开记录。bundle 登记和操作日志 append-only；current/status/catalog 始终反映唯一 `activeBundleId`，回滚也产生新操作记录而不篡改历史。
6. 修复既有 journal 的 candidate/pointer 崩溃窗：`stage='candidate'` 只能说明日志尚未进入 pointer，不能证明 current 未切换。对账必须先读取并校验 current 与候选 `payloadHash`；若 current 已指向候选，按 pointer 阶段前滚或显式恢复已验证旧指针，禁止直接 `discardCandidate()`。任何清理前都必须证明快照未被 current、回滚目标或恢复流程引用。
7. 对账必须从 `status()`/真实 `sync()` 的懒触发改为服务接受内容、同步、进度或写回请求前的强制启动步骤；对账未完成或失败时 fail-closed，然后才能依据 journal 结果恢复持久 job 终态。

持久 job 至少包含：

```text
schemaVersion, serviceInstance, vaultId, jobId, createdBy, dryRun,
requestFingerprint, attempt, status, published,
candidateBundleId, activeBundleId, manifestHash, approvalId,
startedAt, finishedAt, error {code,message}, summary, recovered
```

- `scanning/validating` 为非终态；`ready/invalid/unavailable` 为终态。每次迁移原子持久化，内存 `activeJob` 只负责互斥，不再是查询数据源。
- 重启先完成上述强制 publish journal 对账，再恢复持久 job：候选已完整激活则以 `ready + published=true + recovered=true` 结束；候选废弃或回滚则以 `unavailable + job_interrupted` 结束；dry-run 中断不得伪装成校验通过。不得仅凭 journal 的 `candidate` 阶段判定候选未激活。
- 保留期内完成、失败和新任务之前的旧 job 都按原 ID 返回 200；未知 ID 返回 404，已确认清理的 ID 返回 410 `job_expired`。初版可采用“至少 30 天且最近 100 条”的有界保留，清理不能删除仍被恢复流程引用的 job。
- job 查询仅 owner 或有权 publisher 可用，并按提交者范围限制；响应只给脱敏摘要。现有 OpenAPI 的 `error: string|null` 要与运行时统一为结构化 `{code,message}`。
- 前端从 202 的 jobId 轮询同一任务：`ready + published=true` 才刷新一次 catalog；dry-run 的 `ready + published=false` 只显示校验结果；`invalid/unavailable` 保留旧目录、详情和草稿。轮询网络失败重试同一 job，不重新 POST；组件卸载只停止 UI 轮询，不谎称服务端任务已取消。

#### 5.2.4 学习事实同步语义

同步变更建议形状：

```json
{
  "schemaVersion": 1,
  "changeId": "客户端生成的全局唯一ID",
  "deviceId": "稳定设备ID",
  "kind": "learning.evidence.recorded",
  "occurredAt": "UTC时间",
  "localDate": "YYYY-MM-DD",
  "timeZone": "IANA时区",
  "contentRef": {
    "vaultId": "内容相关事件必填",
    "contentId": "原始或canonical稳定ID",
    "bundleId": "canonical事件可选；legacy ID或待解析outbox必填来源包",
    "aliasVersion": "legacy ID必填，必须与来源bundleId对应"
  },
  "baseRevision": "可变草稿需要；事件可为空",
  "payload": {}
}
```

约束：

- 账户 ID 由服务端会话决定，不能信任请求体里的 `userId`。
- 以 `(accountId, changeId)` 为幂等作用域，持久保存规范化请求指纹、处理状态和原结果；幂等记录与事件追加处于同一事务。同键同请求返回原结果，同键不同请求返回 409 `idempotency_conflict`；跨账户同键互不泄露。
- 进度、掌握度和复习排期由已验证事件重放/投影，客户端不能直接伪造正式等级。内容相关事件保留稳定 canonical content ID，同时可记录产生时的 bundleId；不能按每次发布重置进度。
- `contentId` 为 legacy ID 时，服务端必须使用事件来源的 `bundleId + aliasVersion` 解析，禁止改按 current。来源包已退役、来源包不含该 alias 或解析结果不明确时返回 `conflict` 并保留 outbox，不能把旧事实重定向到另一 canonical ID。
- 打卡使用 `localDate + timeZone`；业务发生时间使用 UTC，但**日志排序只能使用服务端持久序号**，不能用客户端时间。
- cursor 内部绑定 `serviceInstance + vaultId + accountId + syncEpoch + 日志/schema 版本`。跨账户、跨实例、跨 epoch 或无法证明连续的游标必须拒绝并触发全量重同步，不能返回“已最新”。
- pull 的全量快照与增量必须有一致边界；tombstone、幂等记录和冲突元数据的保留期不得短于仍可能重试/同步的设备窗口。日志压缩后旧游标不可继续时返回稳定 `sync_cursor_expired`。
- 删除形成 tombstone；草稿冲突保留双方，禁止默认 last-write-wins。服务端从旧备份恢复导致日志倒退时提升 syncEpoch 并要求全量重同步。
- outbox、cursor 和请求代次按 `serviceInstance + vaultId + accountId + deviceId` 隔离。账户切换立即取消旧代次请求；A 的迟到响应、附件和事件不能写入 B，也不能在 B 会话下重放 A 的 outbox。
- 错误继续采用稳定 `code`，不向后端或客户端暴露绝对路径和堆栈；未知事件类型或 schema 不支持时保留 outbox，禁止丢弃字段后假报成功。

### 5.3 契约版本与能力协商

“不改变旧 URL”不等于向后兼容。权限收紧、注册关闭、真实发布需要审批、新增 409/410 和事件语义变化都必须在契约中显式版本化：

- 内容表示版本、OpenAPI 契约版本和各类同步事件 `schemaVersion` 分开管理；新增可选字段、行为变化和不兼容变化分别记录。
- 健康/状态响应提供 `contractVersion`、支持的最低客户端版本、事件 kind/schema 和能力位。旧客户端—新服务、新客户端—旧服务均使用共享 fixtures 验证。
- 不支持的能力返回稳定 `contract_version_unsupported` 或对应能力错误；写请求保持待处理，不静默降级。新增可选响应字段不能导致旧客户端整页崩溃，未知枚举不得被当成成功。
- 任何破坏性变化按现有 OpenAPI 版本规则升级并记录迁移说明；三端不能只改 URL 就宣称契约兼容。

### 5.4 契约归属

建议把权威 OpenAPI 和共享 JSON fixtures 逐步提升到中立位置：

```text
工程文件/contracts/
  ├─ openapi.yaml
  ├─ content/*.json
  └─ sync/*.json
```

网页端现有 `sync-contract.mjs --check` 继续作为门禁；应用端 C++ 和移动端 Kotlin 不直接 import TypeScript，而是消费同一 JSON 契约/夹具并做兼容性测试。避免三端各自手写一套字段含义。

### 6.1 网页端：最小改动，先完成真实闭环

**复用点**

- `src/content/api.ts`
- `src/content/provider.tsx`
- `src/content/adapter.ts`
- `server/service/server/content/*`
- `server/service/server/learning/*`

**需要补的工作**

1. 在 `网页端/项目/server/config/codeweave.local.json` 显式配置资料库和隔离运行根；该文件保持本机忽略，不提交真实路径。
2. 首次真实发布前先完成 G1：服务端发布权限、附件 CAS、精确审批、提交幂等、持久 job 和 journal 对账；不得把这些留到发布后的“加固阶段”。
3. 将 `ContentProvider.sync()` 改为提交后轮询 `fetchSyncJob()`，直到 ready/invalid/unavailable；区分 dry-run 成功与真实发布成功，只有 `ready + published=true` 才刷新目录。

6. localStorage 暂不清空。后续按注册表逐类接入同步，并把当前选课、最后位置、草稿和待上传记录纳入迁移；不得删除浏览器缓存后宣称迁移完成。

**隔离配置示例（仅供实施时使用，本次未写入）：**

```json
{
  "schemaVersion": 1,
  "vaultRoot": "G:/CodeWeave/工作区/全栈工程师学习资料库",
  "dataDir": "G:/CodeWeave/工作区/data/runtime/unified-pilot",
  "port": 4173
}
```

这里使用新运行根是为了避免把既有 desktop 账户或真实进度带入试点；正式账户迁移必须另走导出、预检和确认流程。

### 6.2 应用端：新增同步源，保留离线原生链

**复用点**

- `ContentRepository` 的校验思想和现有 `Unit/LoadedUnit/Exercise` 领域对象。
- `UiShell.loadPublishedContent()` / `reloadPublishedContent()` 的页面入口。
- 现有后台任务、账户代次、取消和草稿保护。
- `EvidenceStore`、`ProgressStore`、`MasteryStore` 的幂等记录和 `operationId`。
- 现有资料库预览、确认、事务和回滚交互。

**建议结构**

```text
ContentSource（接口/门面）
  ├─ PackagedContentSource  → 现有 native/content，默认离线回退
  └─ SyncedContentSource    → 统一服务快照 + 本地已校验缓存

SyncCoordinator
  ├─ Qt 网络客户端（HTTPS、会话、超时、取消）
  ├─ 内容版本下载与哈希校验
  ├─ 学习事件 outbox / pull cursor
  └─ 冲突、重试、账户切换与代次保护
```

实施要求：

1. 不重写现有 `ContentRepository`；先抽取门面，再新增同步实现。
2. 同步内容写到用户数据根下的独立 `content/<bundleId>/`，先校验 manifest、全部正文和附件哈希，再切换本地 current；不得覆盖源码目录 `native/content`，下载中断不得留下可被误用的半包。
3. 在线内容不可用时继续上一份已验证同步快照；再不可用时明确回退到内置包，并显示来源，不能把回退包说成最新资料库。
4. 未开启在线模式时保持“不监听 TCP、不依赖 Node 服务”的现有行为。
5. 在线模式的资料库写回改走统一服务；Qt 直写入口在该模式下停用。离线默认只暂存证据，不与服务端并发写资料库。
6. 原生旧账本先保留为只读迁移来源；通过现有导出/迁移契约做 dry-run，不自动把旧账户 ID 绑定到新服务账户。
7. 内容缓存、outbox、cursor、下载临时目录和 UI 请求均按服务实例、资料库、账户和设备隔离；账户切换沿用现有代次保护，旧请求不得写入新账户。

## 7. 存储、认证与部署决策

### 7.1 存储

- **只读试点：** 保留现有快照与 JSON 存储，只允许一个服务进程，使用新的隔离运行根；持久 job、角色和邀请写操作必须原子落盘。
- **开启跨端写入或远程模式：** 推荐使用事务型 SQLite 作为单服务默认存储，以版本化 SQL 迁移管理账户、会话、角色、邀请、事件、游标、幂等键和冲突；不建议继续以多个 JSON 文件承担多端同步数据库。
- **多实例或云部署：** 再选择 PostgreSQL；不在单服务试点提前引入分布式设施。
- 内容正文继续采用不可变文件快照，关系数据库存元数据和索引，不把附件无边界塞进数据库。
- 数据目录使用单实例锁；备份采用 SQLite 一致性备份机制并保留必要 WAL 语义，不能在写事务中直接复制三个文件后宣称可恢复。恢复旧备份必须处理 syncEpoch 和内容附件引用。

存储替换属于架构与数据迁移变更，正式实施前需要用户确认备份、回滚和验证方案。

### 7.2 认证、授权与实例生命周期

#### 角色和逐接口权限

权限由服务端持久化授权计算，请求体里的 `userId/role/isPublisher` 一律无效；前端隐藏按钮只改善体验，不是安全边界。

| 能力 | 未登录 | reader | publisher | owner |
| --- | --- | --- | --- | --- |
| 健康与公开能力协商 | 允许脱敏信息 | 允许 | 允许 | 允许 |
| catalog/detail/exercise/asset/离线包 | 拒绝 | 允许（仍受资料库可见范围约束） | 允许 | 允许 |
| 自己的学习事实与同步 | 拒绝 | 仅本人账户域 | 仅本人账户域 | 仅本人账户域 |
| dry-run 与真实发布 | 拒绝 | **403 `publish_forbidden`，零副作用** | 允许 | 允许 |
| 发布 job 查询 | 拒绝 | 拒绝 | 仅本人任务 | 本实例全部任务 |
| 邀请、角色/publisher 管理 | 拒绝 | 拒绝 | 拒绝 | 允许 |
| owner 转移、解绑、可见范围 | 拒绝 | 拒绝 | 拒绝 | 重新认证后允许 |
| 资料库正式写回 | 拒绝 | 拒绝 | 默认拒绝 | 允许；其他账户另授写回权限时必须独立审计 |

- `publicContent=true` 只允许已登录 reader 读内容，不能扩大为匿名访问、发布、job 诊断或写回。
- owner 默认可发布；publisher 不能授予角色、转移 owner 或借 job/错误响应读取源路径。任何授权变更、发布、写回和恢复都记录不含秘密的审计事件。
- 未绑定、owner 记录损坏、`owner.vaultId` 与当前 `vaultId` 不匹配、转移中或恢复中一律 fail-closed：除脱敏健康和受控初始化/恢复入口外，正文、附件、发布、学习事实、可见范围和写回均拒绝。跨库不匹配统一返回 `owner_vault_mismatch` 且零副作用；UI 的 `vaultMatches` 仅作诊断，不能代替服务端授权。
- 服务端必须在创建 job、复用他人 job、写清单/报告/快照之前检查权限；被拒请求前后这些状态逐项不变。

#### 初始化、邀请与 owner 恢复

1. **注册默认关闭。** 普通注册返回 `registration_disabled` 或 `invite_required`，响应不泄露账户是否存在。远程模式不存在“用户表为空即可自助注册并成为 owner”的分支。
2. **一次性 bootstrap。** 由本机管理命令或带外秘密启动，秘密只存哈希，绑定 `serviceInstance + vaultId`，短时效且一次使用。初始化与首个 owner 绑定必须在同一原子操作中完成；并发请求只能一个成功，成功后持久记录 `initializedAt` 并永久关闭入口。
3. **邀请注册。** owner 创建绑定实例、资料库、角色、有效期和单次使用状态的邀请；服务端只存邀请哈希。过期、撤销、跨实例和重复使用均失败且不建立会话。默认只邀请 reader，publisher 需显式授权，邀请不能产生 owner。
4. **取消自助认领。** 普通 `POST /api/learning/owner` 不再承担首次认领。owner 转移要求当前 owner 重新认证、确认目标账户和 vaultId，并以原子状态转换完成；解绑后没有新 owner 前内容保持关闭。
5. **break-glass 恢复。** owner 丢失只能通过本机管理入口或独立一次性恢复秘密处理，不能由 publisher、普通登录或旧邀请完成。恢复、转移、解绑和角色撤销后撤销受影响会话与未使用邀请，保留学习事实、快照和审计记录。

#### 会话、缓存与跨站防护

- 三端复用现有登录和会话语义，避免另起一套长期访问令牌。远程模式必须将会话持久化到事务存储，密码/邀请/bootstrap/恢复秘密只存合适摘要且绝不写日志。
- HTTPS 下 Cookie 增加 Secure；网页继续 HttpOnly/SameSite，应用和移动端的会话秘密放平台安全存储，不写普通偏好文件。
- 内容缓存键至少包含 `serviceInstance + vaultId + accountId + bundleId`；认证与学习接口禁止共享 HTTP 缓存，私有附件继续按 Cookie/Authorization 隔离。
- 登出或账户切换提升本地代次、取消旧请求并清理认证和私密内容缓存。未同步 outbox/草稿仍归属原账户且不能在新区重放；若用户选择彻底删除本账户本地数据，必须先处理或明确确认这些未同步项。
- 角色撤销在下次联网时强制重新验证；发现撤销后对应私密缓存必须立即失效。内容回滚不等于登出，不能误删同账户草稿和 outbox。
- 继续执行请求大小限制、登录/注册/发布/附件限流和写请求跨站防护；不开放宽泛 CORS。网页优先同源，未来拆域时使用明确 origin 白名单并单独审查 CSRF。

### 7.3 部署

- 本机试点继续使用 `127.0.0.1`，不为手机测试直接把现有服务裸露到公网。
- 手机真机联调或任何非 loopback 暴露必须先通过 G4，再配置受信任网络中的 HTTPS 反向代理；监听地址、证书和访问范围属于独立部署变更审批。
- 配置中记录实际 vault/data/static 来源；启动日志、API 错误、发布 job 和离线清单只显示脱敏标识，不泄露私人路径。
- 三端显示 `serviceInstance + vaultId + bundleId + syncCursor/syncEpoch` 的脱敏诊断形式，便于识别“连到了哪一份数据”；不能把 cursor 当认证秘密或跨账户复制。

## 9. 数据扩展方法

当前 `build-pilot.mjs` 硬编码 U01 是合理的试点保护，不适合直接全库运行。扩展时应：

1. 把单单元生成器演进为**批次清单驱动**，每批声明来源、许可、投影、教学单元、练习、阶段和审核指纹。
2. 源哈希变化必须阻断生成，人工复核后才能更新预期值。
3. `topicId` 只追加或按映射退休；改名、拆分、合并必须写 `topic-id-map.json`。
4. 旧课迁移必须写 `legacy-map.json`；无法确认的记录标 `unmapped`，不按标题相似度自动合并。
5. 每批都运行 dry-run，清理全部 blocking；gap 要在产品界面如实显示。
6. 扩大批次不意味着把 `05-外部资料库`、`90-历史归档` 或整个镜像目录加入白名单。

### 9.1 legacy alias 编译规则

`legacy-map.json` 是人工审核后的权威输入；编译器把它转换为当前 bundle 内稳定排序的 `core.legacyAliases`，并让该集合与 `legacyMapHash/mapVersion` 一起参与 bundleId。catalog 同步输出 alias 集合，三端共享类型，不允许 adapter 再读取第二份本地映射。

只有同时满足以下条件的条目进入自动 alias：

- `relation === 'exact'` 且 `reviewStatus === 'reviewed'`；
- `legacyId` 是已知旧内容 ID；
- `newContentId` 属于本次 `publishedContentIds`，不是 draft/retired/仅声明未发布；
- 无一对多、多对一歧义、链式循环、重复 legacyId、canonical ID 冲突；
- 与教学单元中继续保留的 `legacyRefs` 完全一致，否则发布阻断。

`partial`、`split`、`merge`、`pending`、`blocked`、`unmapped` 不自动去重、不自动合并进度；保留 legacy 卡和迁移待办。链式映射若未来允许，必须在编译期展平并校验无循环，禁止运行时逐跳猜测。

### 9.2 目录、深链与选择解析

1. adapter 只过滤已建立 exact alias 的旧卡；空映射基线仍是 1 门新课程 + 61 门旧课。
2. 新增唯一 `resolveCanonicalContentId({bundleId, id})`，详情、旧深链、当前选课、最后位置、掌握度、完成数、复测排期、课程代码草稿和书签统一调用，不复制第二套解析表。
3. 旧 ID 的定位只做解析与显示，不物理改写历史事件或本地原值；目标在当前 bundle 不存在时保持明确错误/迁移待办，不落到另一门课或空白页。
4. 组件卸载、切课和发布切换后，旧代次的 alias 解析结果不得覆盖新 bundle 状态；跨 bundle 不混用映射。
5. 若用户同时存在旧、新 ID 的当前选择或草稿，保留双方并显示迁移冲突，不静默覆盖、求和或重复计数。

### 9.3 学习事实与草稿迁移

- 学习事件保留原始 contentId、解析后的 canonical ID、alias 版本和迁移批次；投影按 canonical 重放，不破坏原始事实。
- 尝试/证据按源事件 ID 幂等合并；同一导入重复执行不得增加完成数、证据数或复习次数。
- 掌握度、复习排期和完成数由已验证事件重放，不按标题、相似度或“较新记录”猜出结果。
- 当前选课、最后学习位置和书签执行一次可回滚重定向；双向冲突保留双方供用户选择。
- 草稿与 outbox 按原账户解析；任何待发送事件仍保留原始 ID 及来源 `bundleId + aliasVersion`，由服务端按来源包解析。跨 bundle 不改用 current；来源退役或映射不明时返回冲突并保留原账户队列，也不把 A 账户队列改写到 B。
- 内容回滚后，发布 B 期间产生的 canonical 事实继续保留；A 中没有该内容时显示“内容不可用但事实保留”，重新激活 B 后恢复解析。
- 账户迁移后的客户端不支持新能力时停止写入并保留 outbox，不能悄悄切回 localStorage/原生账本形成第二权威。

## 11. 回滚策略

- **内容与发布状态：** bundle 登记和操作日志 append-only；恢复上一 `activeBundleId` 是一次新的状态转换，不删除 B 的历史、审批或 job。current/status/catalog 始终指向唯一活动版本；客户端固定读取不可用版本时得到明确 409/410 并整组重建。
- **附件：** 客户端缓存按 bundle 隔离，损坏即拒绝使用；服务端 GC 保留 current、回滚目标、正在发布/下载和受支持离线包的引用，清理中断可恢复。
- **网页：** 关闭新内容源后保留现有 legacy 回退；不得用清空 localStorage 作为回滚。旧选择经 alias 解析失败时保留原值并显示迁移待办，不落到错误课程。
- **应用端：** 切回 `PackagedContentSource` 或上一份已校验同步快照；保留本地账户、草稿、账本和按原账户隔离的 outbox。
- **移动端：** 停用同步只影响在线更新；同账户内容回滚可保留经授权缓存，登出/换账户则关闭私密缓存并按用户确认处理未同步项。
- **学习事实：** 数据库迁移前先备份并在副本演练；事件、tombstone、幂等记录和迁移批次不做破坏性物理删除。内容回滚后新 canonical 事实显示为“内容不可用但事实保留”，不把不可解析当删除；冲突未解决不切换权威源。
- **资料库写回：** 沿用现有事务备份和指纹；回滚被第三方修改阻断时保留现场并请求人工处理。
- **服务数据恢复：** 恢复旧 SQLite/文件备份必须验证内容附件引用完整；日志序号倒退时提升 syncEpoch 并要求客户端全量重同步。
- **本次方案文档：** 未实施任何业务变更，无业务回滚要求；两份文档目前未被 Git 跟踪，尚无仓库内历史版本可用于恢复，后续提交归属由 G0 决定。

## 12. 开工前需要用户确认的决策

以下事项会改变架构、真实数据或部署边界，不能在实施时静默决定：

1. 首次服务范围：仅本机、受信任局域网，还是公网；无论选择哪项，非 loopback 前都必须先过 G4。
2. 第一阶段是否只做只读内容（本方案推荐），以及何时开启学习事实同步。
3. 是否授权对 U01 候选包执行首次正式发布；dry-run 通过不等于自动获得发布授权，发布还必须先通过 G1 并绑定精确候选审批。
4. 跨端写入开启后，是否采用单服务 SQLite；若需多实例则改选 PostgreSQL。
5. 既有账户和旧学习记录是否纳入迁移，以及由哪个服务账户作为资料库拥有者。
6. 首次旧课映射只启用哪些 reviewed exact 条目；partial/split/merge/unmapped 是否只展示待办，不进入自动迁移。

在这些事项确认前，可以进行契约补全、隔离 fixtures、门禁实现、单元测试和客户端适配开发，但不得操作真实数据、切换真实 current、迁移真实账户或暴露远程服务。
