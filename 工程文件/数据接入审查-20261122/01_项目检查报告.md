**原始学习资料已经恢复，CodeWeave 的首批内容接入链也已具备并通过 dry-run；但“资料已补齐”不等于“三端已连接”。**

4. 网页端已有完整的内容 API、前端 Provider 和旧课程兼容层，是接入完成度最高的一端；应用端仍读取独立原生内容包；移动端仍是 Compose 骨架。
5. 三端目前不是同一学习事实数据层。网页端仍有多类账户级数据保存在 localStorage，应用端使用原生本地账本，移动端尚无存储或网络层。
6. 适合先做“**只读内容最小闭环**”，再实施学习记录同步；不宜直接开放三端同时写回资料库。

## 4. 三端工程现状

### 4.1 网页端

**技术栈与工程**

- React 19.2.8、TypeScript 5.9.3、Vite 8.2.1、Vitest 4.1.11。
- Node 服务使用内置 HTTP/文件能力；运行时为 Node `^22.13.0 || >=24.0.0`。
- 依赖锁定为 pnpm 12.4.1；OpenAPI 契约当前为 1.0.0。
- 关键目录：`网页端/项目/src`、`server/service`、`server/contracts`、`tests`。

**已实现的数据能力**

- 内容编译、白名单、稳定主题 ID、来源核验、附件访问、快照哈希、原子指针切换、最近 3 代快照保留和发布事务恢复。
- 已有接口：认证、内容状态/目录/课程/练习/附件/同步、资料库拥有者、正式进度投影、证据暂存/预览/提交/回滚/导出。
- `src/content/api.ts:127-193` 是唯一内容 HTTP 客户端入口；`src/content/provider.tsx:140-247` 负责状态、目录、详情缓存和同步触发。
- `src/content/adapter.ts:358-377` 会把新快照课程与旧内置课程合并，并将旧课标为 `legacy`；首次发布不会仅因快照存在而从网页列表删除旧课。

**仍未统一的数据**

`src/utils/constants.ts` 与 `src/utils/storage-registry.ts` 显示，课程工作区、项目检查点、挑战记录、打卡、掌握度/复测、挑战草稿和外部证据等仍保存在账户作用域 localStorage。它们已有版本化、隔离、导入导出和损坏保护，但不是天然的跨端同步数据。

**当前限制**

- 内容同步 API 是异步任务；`src/content/provider.tsx:236-247` 在收到 202 后立即刷新，`src/components/content-source-view.tsx:125-130` 随即结束 busy。`fetchSyncJob()` 已定义，但生产源码中未发现调用。因此“任务已提交”不能被界面当成“发布已完成”，后续联调必须补轮询和失败呈现。
- 服务只监听 `127.0.0.1`，会话和限流状态在进程内存中，Cookie 当前为 HttpOnly/SameSite=Lax 但未带 Secure。它适合本机单进程，不可直接视作公网/多实例服务。

### 4.2 应用端

**技术栈与工程**

- C++23、Win32、Qt/QML；Node 仅用于构建和内容导出工具。
- 主源码位于 `应用端/项目/native/src`，Qt facade/QML 位于 `native/ui-qt`。
- 默认用户数据根为 `%LOCALAPPDATA%/CodeWeave`；正常原生运行不依赖 Node 服务或 TCP。

**当前内容链**

- `native/src/content_repository.cpp` 读取并校验 hex TSV/TXT 内容包。
- `native/ui-qt/facade/ui_shell.cpp:225-307,462-550` 从 `content_root_` 加载 `curriculum.v1.json` 和发布目录。
- 当前原生资产按现有文档口径为：74 条 published catalog、61 门 UI 课程、13 个挑战、13 个阶段、4 条自动练习、13 条提示；这些是不同的统计对象。
- `scripts/export-native-content.mjs` 在构建期从网页端三个版本化数据模块生成原生包，与“运行时从资料库读取”是两条不同链路。

**当前学习数据与资料库能力**

- `EvidenceStore`、`ProgressStore`、`MasteryStore` 等已有本地幂等账本和服务层。
- `native/ui-qt/facade/vault_writeback_store.cpp` 与 `ui_shell_writeback.cpp` 已实现资料库选择、拥有者绑定、证据预览、确认写回、事务和回滚。
- 这套 Qt 写回与网页 Node 写回是两套实现；没有统一写锁或跨进程协调者，不能让两者并发写同一资料库。

**当前限制**

- 原生课程与新 CodeWeave 内容快照没有运行时适配器。
- 本地账户、正式进度和网页账户没有统一同步协议。
- 已安装版本、源码构建版本和当前构建产物是不同对象；源码检查通过不代表安装版已更新。

### 5.3 配置断点

启动器 `网页端/项目/scripts/launch-web.cmd` 将 `CODEWEAVE_PROJECT_ROOT` 设为 `网页端/项目/server`。本轮未发现：

- `网页端/项目/server/config/codeweave.local.json`
- `工作区/config/codeweave.local.json`

因此，除非外部环境另行注入变量，当前启动不会自动指向：

- `G:/CodeWeave/工作区/全栈工程师学习资料库`
- `G:/CodeWeave/工作区/data/runtime/desktop`

而代码实际默认值为 `<server>/data/vault` 与 `<server>/data/runtime`；本轮对应默认 vault 目录不存在。

另有文档漂移：`server/config/codeweave.config.example.json` 的 `_defaults` 文案及示例值使用 `data/knowledge/vault`、`data/runtime/data`，与 `server/service/server/config.mjs:151-163` 的实际默认 `data/vault`、`data/runtime` 不一致。接入前必须统一口径，不能用猜测路径启动真实数据。

## 6. 主要发现与优先级

| 编号 | 优先级 | 发现 | 影响与处理要求 |
| --- | --- | --- | --- |
| CW-01 | P0 | 新资料库未被当前启动配置引用，且无生效内容快照 | 网页端仍走旧内置回退；先显式配置隔离运行根并完成 dry-run/发布审批 |
| CW-02 | P0 | 原始资料完整，但适配层仍是单单元试点 | 不得把全库直接当已接入；按批次扩展投影、规则、练习和索引 |
| CW-03 | P0 | 三端没有统一学习事实层，Node/Qt 均可独立写资料库 | 在线模式只能保留一个写回协调者；先做只读，再做多端写入 |
| CW-04 | P1 | 网页同步 UI 不等待异步任务终态 | 接入验收前补 job 轮询、失败/冲突展示和取消/重试边界 |
| CW-05 | P1 | 当前服务是本机单进程设计 | 手机或远程访问前补 HTTPS、持久会话、可配置监听/反向代理和事务存储评估 |
| CW-06 | P1 | 新旧 ID 映射为空 | 不得按标题猜测合并进度；旧课继续保留，映射经复核后逐项迁移 |
| CW-07 | P1 | 新适配层与 dry-run 入口尚未提交 | 先确定两个仓库各自的提交边界，防止再次因工作区清理丢失接入资产 |
| CW-08 | P2 | 配置默认文档漂移，主项目无 CI | 修正文档；后续将契约、内容 dry-run 和三端最小门禁纳入 CI |
| CW-09 | 环境 | 文档中的 `corepack pnpm` 当前触发 12.5.1/12.4.1 版本检查失败 | 本轮以 `corepack pnpm@12.4.1` 复验通过；可更新启动/文档命令，但不通过放宽版本检查伪造通过 |

## 8. 建议的下一步

按以下顺序推进，详细设计见同目录 `02_三端数据连接方案.md`：

1. 固化当前未提交的接入资产，明确主仓库与资料库仓库的版本边界。
2. 用隔离运行根完成网页端“配置 → dry-run → 审批发布 → job 终态 → catalog/detail/asset”最小闭环。
3. 抽取中立 OpenAPI/JSON 契约，应用端新增同步内容仓库并保留旧内容包回退。
4. 移动端先完成登录、目录、详情和离线缓存，不在同一阶段承诺代码执行。
5. 最后再迁移 localStorage/原生账本到统一同步协议，并把资料库写回收口到单一服务。
