# CodeWeave 项目简介与检测说明

> 本文件放在 `工程文件/` 下（符合根目录白名单），用于回答「CodeWeave 是什么」与「怎么检测/验收」。
> 仓库根目录按 `AGENTS.md` 不设 README，简介与检测说明统一以本文件为准。内容基于三端各自 `项目/README.md` 与 `工程文件/总工程/*.md` 的事实提炼。

## 一、CodeWeave 是什么

CodeWeave 是一个以「三端工作区」形态组织的**编程学习产品**，不是单端网站，也不是单纯内容仓库。
根目录只允许 `网页端/`、`移动端/`、`应用端/` 三个产品目录 + `工程文件/` + `工作区/` 及若干配置文件，
每端最外层只允许一个 `启动*.lnk`，源码统一放各端 `项目/`。该布局由 `工程文件/工具/check-layout.mjs` 断言强制。

三端各自的产品形态：

- **网页端**（`网页端/项目/`）：可独立部署到服务器的浏览器产品，负责界面、交互状态、API 客户端与网页服务发布源。
  技术栈 React 19.2.8 + TypeScript 5.9.3 + Vite 8.2.1（Rolldown）+ Vitest 4.1.11，含零依赖纯 Node 网页服务（`server/`）与内容发布管线。
  浏览器代码不读服务实现/运行数据，不在客户端启动服务。Node `^22.13.0 || >=24.0.0`，pnpm@12.4.1，MIT。
- **应用端**（`应用端/项目/`）：可独立构建/安装/运行/升级/卸载的 Windows 原生桌面软件。
  C++23 核心 + Win32 便携壳（回滚基线）+ Qt 6 / Qt Quick / QML 预览链，CMake + MSVC。
  外层唯一入口 `启动应用端.lnk` 指向已安装 Qt 应用；构建成功不自动替换安装。
- **移动端**（`移动端/项目/`）：Android/Kotlin UI（`mobile-app/`，Jetpack Compose Material3 + Gradle 8.9 Wrapper / AGP 8.7.3）
  + 独立 C++ 移动核心（`mobile-core/`，C++20）。**当前仍是工程骨架，页面仅显示项目名与「工程骨架已就绪」，未编译验证 APK、未上真机。**

三端共享同一套内容契约与学习事实数据层，**核心方向是代码执行可视化**（节点/边/变量变化/控制台/时间轴/暂停继续/错误与完成态来自同一运行轨迹）。

## 二、检测 / 验收说明（四层门禁）

### 1. 根目录结构自检（唯一根级门禁）
```
node 工程文件/工具/check-layout.mjs
```
校验根目录白名单、三端外层各只一个启动链接、`.local/` 三个 junction 指向、禁止旧目录复活、Qt 构建目录只留 `current`。
`AGENTS.md` 规定：完成修改后必须执行此脚本。成功打印 `Layout passed: three products, one shortcut each, internal tooling, no external project copies.`

### 2. 网页端门禁链
```
cd 网页端/项目
corepack pnpm run verify
```
`verify` 一次串起七步：`audit:boundary → contract:check → typecheck → lint → test:coverage → build → server:check`。
- `scripts/audit-boundary.mjs`：结构边界扫描，禁 `../backend`、`../desktop`、`E:/CodeWeave` 等越界引用。
- `scripts/sync-contract.mjs`：OpenAPI 契约同步/校验。
- 发布前还要对 `/api/health` 与首页执行 HTTP smoke，确认实例身份与安全响应头。
  `/api/health` 实现在 `网页端/项目/server/service/server.mjs`（健康检查最先处理，不读用户文件、不暴露用户信息）；数据损坏时其它 API 返回 503 + `storage_corrupt`。

### 3. 应用端门禁链
```
cd 应用端/项目
node --test tests/*.test.mjs
corepack pnpm run check
```
仓库根执行 `工程文件\工具\构建当前Qt.cmd` 跑 CTest。另有：
- `scripts/native-product-smoke.py`：真实原生 UI 冒烟（Windows，用一次性账户/数据，需 psutil + Pillow，不用调试端口/Electron/真实用户数据）。
- `scripts/verify-qt-install-lifecycle.ps1`、`verify-qt-install-transaction.ps1`：安装生命周期与升级事务验证。
- `scripts/desktop-performance.py`、`qt-window-performance.py`：性能取证。
- 验收阈值：工作集/交互启动增长 ≤20%、安装包 ≤50 MiB、主线程 P95 ≤16.7ms、帧间隔 P95 ≤20ms、编辑 P95 ≤50ms、取消 P95 ≤100ms。

### 4. 移动端门禁链
```
cd 移动端/项目
node scripts/boundary-check.mjs
.\gradlew.bat :mobile-app:assembleDebug :mobile-app:testDebugUnitTest :mobile-app:lintDebug
```
`scripts/launch-mobile.ps1 -Check` 做只读入口检查。移动端当前为骨架，门禁通过不代表手机产品已完成。
